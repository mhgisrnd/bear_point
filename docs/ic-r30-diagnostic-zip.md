# IC-R30 진단 ZIP 공유

수신기의 Bluetooth 탭에서 `10초 기록` 후 저장된 로그를 선택하고 `파일 공유`를 누르면 `ic-r30-diagnostic-<기록 ID>.zip`을 Android 공유 화면으로 전달한다. 공유 대상 앱에서 저장하거나 전송할 수 있다. USB RTL-SDR의 기존 진단 ZIP 공유는 그대로 유지한다.

ZIP 구성:

- `smeter.csv`: 선택한 기록의 원본 CSV 바이트를 그대로 보존한다.
- `metadata.json`: Bluetooth 연결, Icom IC-R30, CI-V 프로토콜, 원본 기록 ID와 파일 수정 시각, 값의 단위 및 포함하지 않는 데이터를 명시한다. 파일 수정 시각을 기록 시작 시각으로 간주하지 않는다.
- `README.txt`: CSV 열과 비교 시 주의할 점을 설명한다.
- 새 기록의 `events.jsonl`: 실제 시작·종료 Unix 시각과 경과 시간, 기록 당시 앱/폰/수신기 정보, 시작 직전 RF Gain·ATT·스켈치 조회값과 조회 시각·오류, 공식 S 대응값, 조회 시작·오류, 연결 종료 사유 및 요약을 기록한다. 확인되지 않은 값에 임의의 S값이나 dBm을 부여하지 않는다.

설정은 시작 전에 읽기 명령으로만 조회한다. 미지원·시간 초과는 값 대신 오류로 남기며, 측정 구간의 S-Meter 조회 간격이나 게이지는 변경하지 않는다. 주파수·모드를 새로 확인한 다음 10초 기록을 시작한다. 준비 시간이 별도로 걸릴 수 있다. 설정은 시작 시점의 값이며 수신기 본체에서 기록 중 바꾼 모든 설정을 추적하는 것은 아니다.

종료 시 `poll_pending_at_stop`이 true이면 응답을 기다리던 조회가 있었다는 뜻이다. 성공한 데이터가 없는 구간에 세기 0을 만들어 넣지 않는다. 기존 CSV 열은 그대로이며, 과거 CSV에는 상세 파일이 없을 수 있다. 파일 공유 시점의 설정을 과거 기록의 측정 조건으로 추가하지 않는다.

기록 목록과 내부 저장은 기존 CSV 형식을 유지한다. 기존에 저장한 로그 및 과거 `ic-r30-test.csv`도 연결 없이 ZIP으로 공유할 수 있다. ZIP은 선택한 기록 하나만 포함하며 목록 건수에 추가되지 않는다. 같은 기록을 다시 공유하면 해당 기록의 ZIP을 교체하고, 선택 삭제 시 원본과 연관 ZIP을 함께 삭제한다. 생성 실패 시 미완성 ZIP을 정리하며 원본 CSV는 유지한다.

IC-R30의 S-Meter는 CI-V 원시값 0~255이며 RTL-SDR의 dBFS나 SNR과 직접 같은 수치로 비교할 수 없다. 같은 주파수·모드·안테나·장소에서 시간과 반복적인 세기 변화, 실제 측정 간격을 함께 비교한다. 서로 다른 기기의 시계 오차도 고려해야 한다. IC-R30 로그에는 오디오나 원본 I/Q가 없으며 `heard` 행은 사용자가 누른 청취 표시다. 자동 비프 검출 결과가 아니다. USB ZIP은 기존 원본 I/Q·오디오·텔레메트리를 유지하므로 두 기록의 포함 데이터는 서로 다르다.

검증: `IcR30LogStoreTest`에서 CSV 바이트 보존, ZIP 구성, 기존 로그 호환, 재공유·삭제, 생성 실패 시 원본 보존을 확인한다. `IcR30TestRecordingTest`와 `IcR30CivTest`로 기존 기록과 통신 처리를 함께 검증한다.
