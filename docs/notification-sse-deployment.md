# 알림 이력 SSE 운영 설정

공유 서버의 변경 사항을 배포하고 앱을 다시 빌드해야 한다. 수신 이력은 FCM이 발송 요청을 접수한 기기별로 저장되며, 실제 기기 표시나 열람을 보장하지 않는다. 발송 이력은 인증된 기기의 공유 등록 시 저장하며 실제 수신 여부를 뜻하지 않는다. 발송 이력은 미확인 수에 포함하지 않는다. 서버 DB 계정에는 `bear_push_history` 테이블과 인덱스를 만들고 `direction` 컬럼을 추가할 권한이 필요하다. 기존 이력은 수신으로 유지하며 과거 발송 이력은 복원되지 않는다.

Nginx가 공유 서버 앞에 있다면 실제 서버 주소와 경로에 맞춰 SSE 경로에 다음 설정을 적용한다. 기존 location과 `proxy_pass`의 경로 치환 규칙을 확인하고 적용해야 한다.

```nginx
location = /api/realtime/notifications/stream {
    proxy_pass http://YOUR_BACKEND;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
}
```

백엔드는 25초마다 연결 유지 이벤트를 보내고 `X-Accel-Buffering: no`를 반환한다. 다른 프록시나 로드밸런서의 버퍼링과 유휴 연결 시간도 확인한다. 설정 적용 전 `nginx -t`로 검사하고, 적용 후 앱에서 알림 수신과 연결 복구를 확인한다. 모바일 앱은 인증 헤더로 스트림을 열기 때문에 인증 정보를 URL에 넣지 않는다.

현재 SSE 연결은 공유 서버 단일 프로세스에 보관한다. 서버를 여러 인스턴스로 운영한다면 발송 처리 인스턴스의 이벤트를 다른 인스턴스로 전달할 별도 메시지 전달 구조가 필요하다. 연결이 끊기거나 앱을 다시 열면 앱이 DB 이력을 다시 조회한다.
