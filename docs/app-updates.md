# Android APK 업데이트

앱 실행 시 한 번 최신 버전을 조회한다. 새 버전이 있을 때만 안내하며, 시작 설정이나 다른 모달이 열려 있으면 닫힌 뒤 안내한다. 자동 다운로드는 하지 않는다. 설정의 **앱 버전** 탭에서 현재 버전, 배포 버전, 변경 내용을 보고 수동으로 다시 확인할 수 있다. 네트워크 실패는 앱 실행을 막지 않는다.

업데이트 서버는 `BEAR_RUNTIME_CONFIG.appUpdateApiUrl` 또는 `realtimeApiBase`의 `/api/realtime`을 `/api/app-updates/latest`로 바꾼 HTTPS 주소를 사용한다. Android 네이티브에서 조회하므로 WebView CORS 정책에 의존하지 않는다. 현재 관리자 서버의 `latest`/`download` API와 연동하며 서버 수정은 필요하지 않다. 업로드한 APK를 공시하고 업데이트 제공을 켜야 앱에 제공된다.

다운로드 버튼을 누르면 배포 정보를 다시 확인한다. 확인 당시 파일 SHA-256과 달라졌으면 다시 조회하도록 안내한다. 다운로드 진행률과 취소를 제공하며 앱 내부 files 저장소의 `app-updates/BearMap.apk` 한 개만 유지한다. 해당 폴더는 백업과 기기 이전에서 제외한다. 검증 완료 후에만 `pending.json`을 기록하며, 앱이나 WebView가 다시 생성되어도 이를 읽어 설치 가능한 상태를 복구한다. 설치 직전 파일 해시와 서명은 다시 검증한다. 실패·취소 시 미완성 파일은 삭제한다. 다운로드 도중 프로세스가 종료되면 다운로드 재시작이 필요하며 이어받기나 별도의 다운로드 백그라운드 서비스는 제공하지 않는다.

파일 크기, SHA-256, APK 패키지·버전·서명을 검증하고 설치 전에도 파일을 다시 검증한다. 동일 API origin의 HTTPS 다운로드만 허용하고 리다이렉트는 따르지 않는다. 패키지는 설치된 앱과 같아야 하며 versionCode는 더 커야 한다. 배포 서버와 설치 앱의 서명도 같아야 한다. APK 크기는 서버와 같은 최대 1GiB로 제한한다.

설치 권한이 없으면 ‘이 출처의 앱 설치 허용’ 설정을 열고 Activity 결과 콜백에서 실제 권한을 재확인한다. 허용되면 파일을 검증하고 설치 전용 Intent로 Android 설치 화면을 이어서 연다. 권한이 거부되면 **설치 계속**으로 재시도할 수 있다. 화면이 재생성된 경우에도 저장된 완료 정보에서 복구하여 설치를 계속할 수 있다. Android 설치 확인은 사용자가 진행한다. 설치 취소·실패는 실제 Activity 결과로 구분한다. 수신이나 이동기록 서비스가 실행 중이면 설치를 차단하고 먼저 종료하도록 안내한다. 기존 기록을 삭제하거나 서비스를 자동 중지하지 않는다.

빌드의 versionName/versionCode는 `android/app/build.gradle`에서 관리한다. 이번 기능 추가만으로 버전 번호를 자동 증가시키지 않는다. 실제 공시할 빌드에서는 같은 서명 키를 사용하고 관리자가 버전 값을 올려야 한다. 기능을 갖추지 않은 기존 앱에는 처음 한 번 수동 APK 설치가 필요하다.

검증: `node --test tests/app-updates.test.cjs`, Android `AppUpdatePolicyTest`, 브라우저의 자동 안내·수동 확인·다운로드 동의·진행률·권한 재시도·모바일 레이아웃을 확인한다. 실기기 설치 허용/설치 완료와 실제 대용량 다운로드는 별도 확인이 필요하다.
