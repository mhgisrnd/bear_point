# SDR 연결·IQ 분석·WFM 방송 수신 테스트

## 개별 CW 협대역 펄스 검출: cw-pulse-v1 / ui52

`SdrCwDetector`는 기존 청취를 차단하거나 주파수를 변경하지 않고, 청취 AGC/BFO 전 48 kHz `channelIq`를 분석합니다. 2048점 Hann FFT(23.4375 Hz/bin, 42.67 ms 창)를 256표본(5.33 ms)씩 이동하며 표시용 peak hold는 사용하지 않습니다. 기존 필터의 검증된 중앙부인 설정값 ±900 Hz를 탐색하고 약 211/398 Hz 후보 대역을 평가합니다. 원래 CW 필터의 알려진 응답을 주파수별로 보상하여 전력 기준을 맞추지만, 이는 손실된 RF SNR이나 하드웨어 감도를 복구한다는 뜻이 아닙니다.

잡음은 후보 대역의 약 1.37초 중앙값과 guard 구간 밖 인접 주파수의 추정값 중 큰 값을 사용합니다. 펄스 시작 SNR은 6 dB, 유지 기준은 2.5 dB입니다. 최소 약 8 ms, 최대 450 ms의 **FFT 포락선 구간**을 평가하므로 기록된 지속시간을 실제 발신기의 키잉 폭으로 그대로 해석하지 않습니다. 광대역 잡음 바닥이 6 dB 넘게 상승하면 12 dB 이상의 후보 대비를 요구하여 광대역 충격 잡음을 구분합니다. 지속 반송파는 펄스로 확정하지 않습니다.

같은 주파수에서 두 펄스가 관측되면 최근 간격을 학습하여 예상 시각 근처의 약한 후보를 보조 검출합니다(4.5 dB 및 한 hop 이상의 포락선). 고정 600 Hz 오차나 1.52초 간격은 사용하지 않습니다. 첫 펄스와 충분히 강한 펄스는 반복 간격과 무관하게 검출합니다. `cwCadenceAssisted`로 보조 판정을 구분합니다. 후보 주파수는 약 5초 추적하고, 수신 데이터 불연속·주파수 변경·재시작 시 이전 상태는 초기화합니다.

방향 추적은 신뢰도/SNR을 칸수로 환산하지 않습니다. 검출 폭이 바뀌어도 항상 약 398 Hz의 고정 기준 대역에서 잡음을 뺀 후보 신호 전력을 사용합니다. 상대 dBFS 기준의 고정 6 dB 간격(-100 dBFS부터)의 10칸이며 **IC-R30 S미터 보정값이나 안테나 입력 dBm이 아닙니다**. RF Gain·측정 대역폭이 같을 때 방향별 비교에 사용합니다. 약신호의 잡음 차감 오차와 최대값 선택 편향은 남으므로 현장 검증이 필요합니다. 마지막 펄스 전력은 350 ms 표시하고, 전력 숫자와 최근 후보 상태를 구분합니다. 신호를 확정하지 못해도 기존 청취는 계속됩니다.

기존 게이지 모양과 설정 주파수 선을 유지하며 CW 후보 선만 추가합니다. 새 필드가 없는 기존 스냅샷은 종전 표시로 처리합니다. `cwConfidence`는 0=추적 후보 없음, 1=단발 후보, 2=반복 후보 상태이며 확률이나 발신기 식별 결과가 아닙니다. 다른 CW 간섭원이 같은 범위에 있으면 오인할 수 있으며 등록 개체를 자동 변경하지 않습니다. 대역 탐색의 기존 검출 방식은 이번 변경 대상이 아닙니다.

10초 ZIP에는 원본을 계속 보관하고 `cwDetectorRevision`, 후보 주파수/편차, 검출/방향 측정 대역폭, 검출 신호·잡음·대역 전력, `cwSnrDb`, 방향 전력, `cwPulseCount`, 펄스 시각·수집 순번·포락선 지속시간·간격, 광대역 잡음 상승, 보조 판정 여부, 프레임 범위와 처리시간(`cwDetectorMs`)을 추가합니다. 기존 전체 채널 측정값도 남겨 전후 비교할 수 있습니다. 원본 I/Q 및 개별 FFT 배열은 WebView에 추가 전달하지 않습니다. 오디오 예상 재생 대기에 펄스 분석 경과 시간을 반영하지만 실제 스피커와의 동기화는 실기 측정이 필요합니다.

자동 검증에는 주파수 양쪽·0 Hz·다른 블록 길이, 고정 대역 방향 전력, 순수 잡음 60초, 광대역 잡음 펄스 60초, 지속 반송파가 포함됩니다. 이 합성 제어 시험은 현장 발신기 OFF 검증을 대체하지 않습니다. 기존 약신호 파일은 개발/검토에 사용한 자료이므로 독립적인 검출률 검증 자료로 주장하지 않습니다.

현장에서는 포화 없는 정상 수신, IC-R30만 명확한 약신호, 그 위치의 안테나 방향별 수신, 같은 환경의 발신기 OFF를 각각 고정 상태로 10초씩 2~3회 기록합니다. 거리·안테나 방향·발신기 상태·IC-R30 청취 상태는 ZIP과 함께 메모합니다. 가까운 위치의 ADC 포화 원본은 선형 감도 보정에 사용하지 않습니다. 원거리 개선과 현장 오탐률은 아직 검증되지 않았습니다.

## 연속 수집·재생·기록 분리: async-usb-v1 / 진단 schema 3

개별 CW/WFM은 공식 librtlsdr 비동기 전송 API를 전용 USB 스레드에서 사용합니다. 콜백은 원본과 순번·콜백 시각·원본 바이트 오프셋만 제한된 대기열로 전달합니다. 복조·화면 분석·파일 저장을 수행하지 않습니다. 블록은 표본율에 따라 약 32 ms 이하로 구성하고 앱 수신 대기열은 약 96 ms를 기준으로 제한합니다. 과부하 때는 오래된 블록을 버리고 블록·바이트 누락량을 누적합니다. 다음 복조 블록의 오프셋이 불연속이면 복조·게이지·스펙트럼의 이전 상태와 대기 중 오디오를 초기화합니다. 정지·분리 때는 비동기 취소가 완료된 후 라이브러리와 USB 파일 디스크립터를 닫습니다. 대역 탐색의 주파수 변경 루프는 기존 동기 수집을 유지합니다.

청취는 약 64 ms를 준비한 뒤 시작하며 Java PCM 대기열은 최대 96 ms입니다. AudioTrack에 실제로 먼저 쓴 뒤 재생을 시작하고, 하드웨어 버퍼가 비었을 때만 재준비합니다. 하드웨어 버퍼 크기 자체는 기기가 보고한 최소값 이상으로 설정합니다. 재생 헤드 위치로 버퍼 대기 시간을 추정하고, 해당 블록의 화면 게시에도 최대 150 ms의 예상 재생 대기를 적용합니다. 이는 기기 스피커까지 정확히 측정한 동기화가 아니며, UI 갱신 주기와 기기 출력 지연이 남습니다. `presentationDelayClamped`는 이 한도를 넘는 추정 대기 상태를 나타냅니다. 네이티브와 Java는 CLOCK_BOOTTIME/elapsedRealtime의 같은 시간축을 사용합니다. 게이지 곡선·청취 증폭·RF Gain 설정은 이 작업에서 변경하지 않습니다.

진단 원본은 8비트 바이트 배열로 전달하여 double I/Q로 변환했다가 되돌리는 비용을 제거했습니다. 파일 쓰기는 별도 제한 대기열의 저장 스레드가 수행합니다. 저장만 밀리면 수신을 대기시키지 않고 기록을 `writer-overflow` 사유로 부분 종료합니다. 미완료 여부와 누락 블록·바이트 수를 메타데이터와 UI에 표시합니다. 이미 접수한 기록은 순서대로 저장한 뒤 마무리하며, 저장 작업이 없을 때는 반복적으로 짧은 주기로 깨우지 않습니다.

schema 3에는 `sourceSequence`, `sourceByteOffset`, `sourceReceivedMs`, `sourceCallbackIntervalMs`, 수신 큐 나이·깊이·최대 깊이·누락량, 저장 큐 깊이·최대 깊이가 추가됩니다. `decoderWaitMs`는 복조 작업이 수신 큐에서 기다린 시간이며 실제 USB 전송 시간이라고 해석하지 않습니다. `streamReadStatus`도 큐 읽기/스트림 종료 상태입니다. `usbDeliveredBytes`는 콜백이 받은 누적 원본량이며 `blocks.csv`의 `usb_offset`은 복조에 전달된 양을 누적한 기존 오프셋입니다. 둘의 차이와 앱 누락량으로 앱 내부 과부하를 구분할 수 있지만 동글 하드웨어에서 전달하지 못한 표본 수까지 확정하지는 못합니다. 오디오에는 마지막 쓰기 블록 순번·출력 대기·소스부터 예상 출력까지의 지연·재준비 횟수·flush된 표본 수도 남깁니다.

AudioTrack 재생 헤드와 기록한 PCM 프레임 구간을 대응시켜 `playingSourceSequence`를 기록하며, 화면 게시 시각(`displayPublishedMs`)과 당시 오디오 블록(`audioSourceSequenceAtDisplay`)도 보관합니다. 재생 헤드 위치는 기기 스피커의 실제 음압 측정값이 아니므로 최종 싱크는 실기 검증이 필요합니다.

100 ms 표시 창의 최대 전력이 어느 원본 블록에서 나왔는지도 `signalPeakSourceSequence`/`meterPeakSourceSequence`로 구분합니다. 새 CW 피크가 창 앞부분에서 발생했다면 경과한 블록 시간만큼 화면 대기를 줄여, 이미 재생된 피크에 불필요한 지연을 더하지 않습니다. 게이지의 350 ms·스펙트럼의 250 ms 피크 유지는 기존 시각화 동작이므로 과거 피크가 잠시 남는 것과 스트림 대기 지연은 구분해야 합니다.

## CW 게이지 개선: cw-channel-relative-v2

CW 강도는 청취·확대 스펙트럼과 같은 선택 주파수 중심의 복소 채널에서 `I²+Q²`로 측정합니다. 기존 700 Hz 변환 후 실수 필터를 쓰던 게이지 전용 경로를 제거해 주파수 오차의 양쪽에 대칭으로 반응하도록 했습니다. 3 ms 전력 추정과 2.56초 잡음 기준 추정은 유지하며, 청취 증폭·BFO·스펙트럼 표시용 피크 유지에는 영향을 받지 않습니다. WFM 게이지와 대역 탐색 후보 판단은 변경하지 않습니다.

표시는 작은 변화도 읽도록 잡음 대비 상승량에 상대 곡선을 적용합니다. 1~10칸 시작점은 각각 3/3.5/5/7/10/14/19/25/32/40 dB입니다. 이전 6 dB 첫 칸 제한을 완화하면서 낮은 단계의 간격을 좁혔습니다. 높은 값은 즉시 반영하고 최근 피크를 350 ms 유지한 후 현재 단계로 돌아갑니다. 유지 중에는 `최근 피크 유지`를 표시합니다. 이는 IC-R30과 입력을 대조해 보정한 절대 S단위가 아니며, 비프음으로 확정하는 판정값도 아닙니다. 반복 주기 탐지를 게이지 표시의 필수 조건으로 사용하지 않습니다. 잡음의 일시적인 상승도 반영될 수 있습니다.

수신 스냅샷은 `signalLevel`, `signalLevelHeld`, `signalLevelExcessDb`, `signalMeterRevision`을 제공합니다. 진단에는 `meterRevision`과 원래 창 단계·실제 표시 단계·피크 유지 여부가 포함되어 순간 측정과 화면 유지 반응을 구분할 수 있습니다. 구버전 스냅샷에는 기존 화면 계산을 적용하여 기존 결과를 읽을 수 있게 합니다. 측정 경로 변경 전후의 dBFS 값은 필터 응답 차이가 있으므로 동일 기준으로 직접 비교하지 않습니다.

## 수신 진단 schema 2: 시간·오디오·실제 설정 확인

`10초 기록`의 ZIP에 `telemetry.jsonl`을 추가했습니다. 기록 전 최대 3초의 약 100 ms 간격 기준 자료와, 기록 중 각 USB 블록의 자료를 함께 보관합니다. USB 읽기 시간·반환 코드(타임아웃 포함), JNI 전체 시간, 네이티브 처리 시간, 복조와 PCM 전달 시간, 스펙트럼 시간, 루프 시작 간격, 레지스터 읽기 시간, 기록 쓰기 시간을 구분합니다. JNI 처리·복조·전체 시간은 서로 포함 관계가 있으므로 단순히 모두 더하면 안 됩니다. 기록 중 I/Q 전달·파일 쓰기 부하가 기준 구간과 얼마나 달라지는지 비교할 수 있습니다. 파일 쓰기 누적 시간은 I/Q 재구성과 버퍼 기록 구간이며 전체 UI/포장 시간을 뜻하지 않습니다.

각 블록에는 실제 표본율과 USB 바이트 수, ADC 최솟값·최댓값·I/Q 평균·RMS, 신호·잡음 전력, 게이지 창의 상대 전력과 단계, 스펙트럼 피크 주파수·전력, 오디오 생성 표본 수를 기록합니다. 게이지 창 값은 해당 시점까지의 누적 피크이며 WebView에 게시되는 최종 창 값과 경계가 다를 수 있습니다. 오디오에는 큐 깊이, 누적 전달·쓰기·누락 표본 수, 버퍼 언더런, 빈 큐 대기 횟수, 출력 장치, 청취 증폭, Android 미디어 음량을 기록합니다. 누적값은 수신 프로세스 기준이므로 첫 블록과 마지막 블록의 차이로 판단합니다. WAV는 여전히 스피커 측정음이 아닌 처리된 PCM입니다.

기록 시작에 USB 소유 작업 스레드에서 RTL AGC 제어 레지스터(0x19)를 읽고, FC0013이면 모드(0x0d), IF(0x13), LNA(0x14), VHF 추적(0x1d)을 읽습니다. 각각 전송 결과와 `readOk`를 함께 저장합니다. 미지원 튜너 항목과 실패한 읽기는 값 -1이며 읽기에 성공했다고 간주하지 않습니다. IF 레지스터 숫자는 dB 수치가 아닙니다. 이 진단은 이득·AGC 설정을 변경하지 않으며 I2C 접근용 repeater를 읽기 후 닫습니다. 기기 모델·Android 버전·앱 자산 개정도 함께 저장합니다.

`metadata.json`에는 schema_version=2, 시작·마지막 설정, 원본 표본 시간, 전달된 표본 시간, PCM 표본 수가 추가됩니다. `blocks.csv`의 USB 오프셋은 앱에 전달된 바이트 기준이며 하드웨어의 순번이 아닙니다. 따라서 표본 시간 부족과 처리 지연은 관찰할 수 있지만, 받지 못한 하드웨어 표본 수를 직접 확정할 수는 없습니다. 수집 중 실패는 수신을 중단하지 않고 진단 오류로 표시합니다.

새 기록은 앱 내부 `files/sdr-diagnostics`에 보관합니다. 기록마다 별도 폴더를 만들고 ZIP을 완성한 뒤 확정 이름으로 바꾸므로 부분 ZIP은 목록에 노출하지 않습니다. 저장된 기록은 앱 재실행 시 다시 검색하고, 기존 캐시의 완료된 진단 ZIP도 검색합니다. 수신기를 분리한 상태에서도 `수신 진단`의 기록 선택과 공유가 가능합니다. 공유는 선택한 기록 식별자를 앱 내부 목록에서 찾으며 임의의 파일 경로를 받지 않습니다. 앱 삭제·데이터 삭제 시에는 기록도 삭제됩니다.

## 수신 알림에서 화면으로 복귀

고정 수신·대역 탐색 알림 본문은 전용 `OPEN_SDR_RECEIVER` Activity Intent를 전달합니다. 앱이 이미 열려 있으면 `handleOnNewIntent`에서, 새로 열리면 Capacitor 초기 Intent 전달 경로에서 처리합니다. 수신 화면 열기 요청은 프로세스 상태에 보관하여 WebView 초기화 이전에 클릭해도 초기 상태 조회로 전달됩니다. 화면을 열고 현재 수신 주파수·모드·결과를 복원한 뒤 해당 요청 번호만 확인 처리합니다. 같은 요청의 늦은 응답으로 창을 반복해서 열지 않으며, 새 알림 클릭은 새 요청으로 처리합니다. Activity 재생성 시 기존 실행 Intent가 다시 요청되지 않도록 소비합니다. 이 경로는 수신 시작·정지·USB 연결·청취 설정을 변경하지 않습니다. 알림의 별도 `정지` 버튼은 기존 정지 동작을 유지합니다.

## 고정 CW 스펙트럼: 대상 주파수 중심 ±3 kHz

고정 CW 수신의 스펙트럼은 선택 주파수를 중심으로 총 6 kHz만 표시합니다. 148.241 MHz의 경우 148.238~148.244 MHz이며, 중앙에 `대상`을 표시합니다. 내부 USB 중심은 DC 영향을 피하기 위해 계속 12 kHz 낮게 잡지만 화면 축에는 사용하지 않습니다. 실제 FFT는 기존 CW 복조기의 BFO·청취 증폭 이전 48 kHz 복소 채널을 재사용합니다. 1024점 Hann FFT와 50% 중첩으로 약 46.875 Hz 해상도를 얻고 중앙 128개 bin만 표시합니다. 단순히 기존 1 kHz 간격 결과를 늘려 그리는 방식이 아닙니다. 수신 정지 후에도 마지막 그래프의 대상 주파수를 유지하며, 중심 bin을 하드웨어 DC로 오인해 최대점 후보에서 제외하지 않습니다.

짧은 신호의 250 ms 피크 유지를 사용하고 세로축은 실제 dBFS/bin 값을 유지하면서 60 dB 범위로 자동 조절합니다. 피크 표시는 대상 주변에서 가장 큰 점이며 비프음 확정을 의미하지 않습니다. 청취 증폭·게이지 수치와는 독립적이고 RF 감도나 소리 필터를 변경하지 않습니다. 대역 탐색과 WFM의 기존 분석은 유지합니다.

일반 고정 CW 표시에서는 매 블록의 전체 고속 I/Q Java 복사와 광대역 FFT를 생략합니다. 원본 I/Q는 사용자가 진단 기록을 실행할 때만 내보냅니다. 이 변경으로 분석 부하를 줄이지만, 현장 기록의 경과 시간과 표본 시간 차이가 해소됐는지는 태블릿에서 별도로 확인해야 합니다.

## CW 청취 경로 개선과 IC-R30 비교

앱의 CW는 수신 I/Q에서 실제 반송파를 700 Hz 청취음으로 변환하는 방식입니다. 신호 세기가 임계값을 넘으면 별도 비프음을 합성하는 방식이 아니며, 잡음이나 작은 비프음을 음소거하는 스켈치도 없습니다. IC-R30의 공개 사양은 CW 수신과 DSP 처리를 확인할 수 있지만 내부 필터·자동 레벨 알고리즘은 공개되어 있지 않아 동일 구현 또는 동일 수신 감도라고 단정할 수 없습니다. [공식 사양](https://www.icomjapan.com/lineup/products/IC-R30/?open=1), [SSB/CW 음량을 6 dB 높인 공식 펌웨어 이력](https://www.icom.co.jp/support/drivers/3540/).

기존 청취 경로는 700 Hz 변환 후 실수 저역 필터를 적용하여 선택 RF 주파수의 양쪽 응답이 비대칭이었습니다. 청취 경로를 선택 주파수 중심의 복소 채널 필터 → 48 kHz 변환 → 700 Hz BFO → DC 차단 → 청취 레벨 조절로 변경했습니다. 채널 필터는 I/Q 각각 2.5 kHz 단일 극 필터 네 단을 사용하며 IC-R30의 필터 응답을 복제한 것은 아닙니다. USB 중심 주파수는 목표보다 12 kHz 낮춰 DC 영향을 피하고, 이 오프셋 수신에서만 입력 DC 추정을 제거합니다. 기존 신호 세기 계산 경로와 게이지 기준은 유지합니다.

청취 증폭은 기본 `자동`입니다. 3 ms 공격·500 ms 해제의 진폭 추정과 최대 약 36 dB 증폭을 사용하며, gain 증가에는 250 ms 시정수를 적용합니다. 수동은 원음 또는 2~64배(6~36 dB)로 수신 중 변경할 수 있습니다. 갑자기 큰 신호가 들어오면 부드러운 제한 처리를 적용합니다. 청취 증폭은 이미 들어온 신호와 잡음을 함께 키우며 RF 감도나 신호 대 잡음비를 높이지 않습니다. 실제 스피커 음량은 Android 미디어 음량·출력 장치에도 영향을 받습니다.

`tests/cw-reference.cjs`는 운영 코드의 IIR·AGC를 재사용하지 않는 FFT 기반 1.8 kHz 복소 채널 기준 복조기입니다. 동일한 약한 잡음 섞인 합성 I/Q에서 운영 청취 경로의 SNR이 기준보다 3 dB 넘게 낮아지지 않는지 검증합니다. 이는 공개 CW 선택도에 참고한 독립 비교이며 실제 IC-R30 측정 결과가 아닙니다. 추가 검증은 주파수 오차 양쪽 응답, 짧은 펄스, 표본율·블록 경계, 증폭 전후 RF 수치 불변, DC가 가짜 비프음을 만들지 않음, 강한 신호 제한을 포함합니다.

### 현장 진단 기록

개별 CW 수신 중 `수신 진단`을 펼쳐 `10초 기록`을 누르면 앱 내부 저장공간에 I/Q와 청취 PCM을 기록합니다. 기본 1.024 MS/s에서 I/Q는 약 20 MB이며 50 MiB로 제한합니다. 수신 정지·주파수 전환 시 진행 중 기록은 부분 기록으로 마무리합니다. 준비 완료 후 사용자가 `파일 공유`를 눌러 공유할 수 있고 자동 전송은 없습니다. 진단 중 청취 증폭 변경은 잠시 막습니다.

ZIP에는 `samples.cu8`(unsigned 8-bit I/Q), `received-audio.wav`(48 kHz, mono, PCM16), 실제 튜너·적용 Gain·PPM·주파수·증폭 설정을 담은 `metadata.json`, `blocks.csv`가 들어 있습니다. 네이티브 FFT 버퍼에서 완전한 프레임만 내보내므로 일부 블록 꼬리는 누락될 수 있으며 누락량·USB 오프셋을 인덱스에 명시합니다. 무손실 연속 기록이라고 가정하면 안 됩니다. 기록된 WAV는 스피커에서 마이크로 녹음한 소리가 아닌 청취 처리 결과이며 Android 재생 큐 누락이나 실제 스피커 출력은 별도로 확인해야 합니다.

같은 위치·안테나에서 IC-R30에 비프음이 들리는데 앱에는 안 들리는 상황을 기록하여 독립 복조와 비교합니다. 원본에 신호가 있는데 운영 청취 경로에서 사라지면 소프트웨어 원인으로 계속 조사합니다. 두 복조기 모두에서 신호를 확인하지 못하면 RF Gain·보정·USB·간섭·튜너 등 입력 경로를 점검합니다. 이 결과만으로 하드웨어 한계가 입증되는 것은 아니며 실제 현장 원본과 비교 수신이 필요합니다.

## 작성 중 관측점의 SDR 대상 갱신

새 관측점 등록창을 열어 둔 채 수신기에서 다른 개체·주파수를 확인하고 다시 관측점 등록을 누르면 기존 폼을 재사용합니다. 개체 코드와 SDR 출처 주파수, 취소 시 돌아갈 탐색 화면만 갱신합니다. 명칭·위치·방위·담당자·팀·감지기 등 작성 내용은 초기화하지 않으며 자동 저장하지 않습니다. 취소하면 가장 최근 탐색으로 돌아갑니다. 저장 중이거나 기존 저장 관측점을 수정하는 창은 대상 갱신을 막아 편집 상태를 보호합니다.

## 신호 세기와 스펙트럼 분할 표시

화면 폭이 600px 이상이면 수신 신호 세기와 스펙트럼을 좌우 같은 폭으로 배치합니다. 수신 데이터·대역 전력은 신호 세기 아래 왼쪽 영역에 함께 표시합니다. 좁은 모바일에서는 그래프 눈금과 수치를 읽을 수 있도록 세로 배치를 유지합니다. 신호 세기 10단계와 판단 기준은 변경하지 않았습니다.

분할 화면의 스펙트럼 표시 높이는 128px이며, 실제 표시 높이와 기기 배율에 맞춰 캔버스와 눈금을 그립니다. 작은 높이에 기존 캔버스를 압축해 글자가 함께 작아지지 않도록 했습니다. 스펙트럼은 계속 표시 전용입니다.

## 스펙트럼 표시 전용

스펙트럼의 드래그 주파수 조절, 선택 주파수 미리보기, 되돌리기 버튼을 제거했습니다. 수신 중·정지 후·오류 상태 모두 신호 그래프와 측정 요약만 표시합니다. 그래프를 터치하거나 끌어도 주파수가 바뀌지 않으며 스크롤을 가로채지 않습니다. 주파수는 개체 카드 선택 또는 기존 직접 입력·숫자별 화살표로 변경합니다. 공통 ± 조절 디자인은 별도 시안이며 아직 앱에 적용하지 않았습니다.

## 상세 설정 접기·펼치기

감도(Gain), 주파수 보정(PPM), 대역 탐색 감지 기준을 `상세 설정` 안에 묶었습니다. 수신기 팝업을 열 때는 접힌 상태이며 제목을 눌러 펼칩니다. 접어도 설정값은 유지되며 수신 시작과 주파수 전환에 그대로 적용됩니다. 가로 모드 키보드 검색 중에는 상세 설정도 숨겨 검색 공간을 확보합니다.

## 기기별 개체 즐겨찾기

개체 코드 영역 오른쪽 위의 별 버튼으로 즐겨찾기를 추가·해제합니다. 활성 상태는 노란 별로 표시하며 수신 주파수 선택과 분리되어 있습니다. 목록 개수 오른쪽의 즐겨찾기 필터를 켜면 저장한 개체만 표시하고, 번호 검색은 필터 결과 안에서 적용합니다. 별·필터 변경은 수신을 시작·정지하거나 청취 주파수를 바꾸지 않습니다.

정규화한 개체 코드 목록을 기기 localStorage의 `bearpoint.sdrAnimalFavorites.v1`에 저장합니다. 서버에는 전송하지 않으며 앱 재시작이나 APK 갱신 후에도 유지됩니다. 개체 ID나 주파수 변경은 즐겨찾기에 영향을 주지 않습니다. 저장 실패 시 별을 저장된 상태처럼 바꾸지 않고 오류를 표시하며, 잘못된 저장 데이터가 앱 수신 초기화를 막지 않도록 처리합니다.

## 개체 검색과 가로 모드 키보드

검색창에 포커스가 있고 가용 화면 높이가 480px 미만이면 검색 중심의 간소화 화면을 사용합니다. 제목을 줄이고 하단 수신 버튼과 다른 설정은 잠시 숨겨 검색창과 한 줄의 가로 검색 결과 공간을 확보합니다. 키보드에 가리지 않는 visualViewport 높이를 계속 반영하며 검색창을 보이는 영역에 유지합니다.

검색창 Enter 키와 검색 폼 submit(IME 검색 동작)은 기본 제출을 막고 입력 포커스를 해제합니다. 조합 입력 중 Enter는 처리하지 않습니다. 개체 카드를 선택하거나 검색을 마치면 일반 화면을 복구합니다. 브라우저에서 키보드로 줄어든 화면 높이를 재현한 테스트이며 실제 Android IME 확인은 태블릿에서 진행해야 합니다.

## 개체 선택과 수신 주파수 공용 화면

개체 카드는 왼쪽에 개체 코드, 오른쪽에 실제 주파수를 포함한 A/B/C 버튼을 세로로 표시합니다. 버튼을 누르면 개체와 등록 주파수를 한 번에 선택합니다. 등록된 슬롯만 표시하고 선택 슬롯을 강조합니다. 별도 A/B/C 선택 영역은 제거했습니다. 선택한 값은 기존 수신 주파수 숫자·화살표에 반영되며, 수동 조절로 주파수가 달라지면 기존 개체 선택과 관측점 등록 대상을 해제합니다.

개별 수신 중에도 목록과 검색을 사용할 수 있습니다. 다른 슬롯을 누르면 기존 수신 종료를 기다린 뒤 동일한 CW·Gain·PPM 설정으로 새 주파수 수신을 시작합니다. 같은 주파수를 다시 누르면 재시작하지 않습니다. 전환 중에는 중복 조작을 막고, USB 해제나 팝업 닫힘이 발생하면 새 수신 시작을 취소합니다. 새 주파수 데이터가 들어오기 전에는 이전 결과로 관측점 등록을 허용하지 않습니다. 개별 수신 시작·전환 시 결과 영역으로 자동 스크롤하지 않습니다.

현재 설정 주파수와 정수 Hz 단위로 일치하는 등록 개체를 전체 목록에서 찾아 수신 주파수 MHz 오른쪽에 코드를 표시합니다. 동일 주파수의 개체가 여러 개면 코드를 함께 표시합니다. 이 표시는 주파수 데이터의 일치를 뜻하며 실제 송신기 식별이나 개체 자동 선택을 의미하지 않습니다. 일치 항목이 없으면 코드 표시를 숨깁니다.

목록과 수신 주파수 사이에 반복되던 선택 개체·주파수 안내 문구와 최소 높이를 제거했습니다. 개체 정보는 카드의 선택 표시와 수신 주파수 제목 옆 코드로 확인하며, 목록 아래 여백은 4px로 줄였습니다.

## 개체 목록 가로 스크롤

개별 탐색의 개체 목록은 두 줄의 작은 카드로 좌우 스크롤합니다. 목록 내부의 세로 스크롤을 제거하고 세로 제스처는 팝업 스크롤로 이어지도록 했습니다. 작은 화면에서는 다음 카드 일부가 보여 좌우 이동을 알 수 있으며, 검색 시에는 목록을 처음으로 이동합니다. 신호 상태 갱신 중에는 가로 스크롤 위치를 유지합니다.

카드 높이는 등록 주파수 개수와 관계없이 98px로 통일합니다. 이전 112px보다 낮추되 두 줄의 카드 경계를 일정하게 맞춥니다. 주파수 선택 행은 32px이며 값이 적은 경우 오른쪽 영역 안에서 세로 가운데로 정렬합니다.

## 수신 주파수 소수점 5자리

개별 탐색의 수신 주파수를 정수 3자리와 소수 5자리(최소 10 Hz)로 조절합니다. 기존 숫자별 화살표와 직접 편집 방식을 유지하고, 팝업 너비를 늘리지 않고 숫자 크기와 간격을 줄였습니다. 개체 선택 해제, 수신 시작·복원 시에도 끝자리를 유지합니다. 수신 결과에도 실제 주파수를 표시합니다.

직접 편집에서 마지막 숫자를 입력하면 허용 범위를 검사한 뒤 자동 완료하고 숫자 셀의 포커스를 해제합니다. 키보드 힌트는 완료(done)로 지정하며 Enter, 마지막 셀의 Tab, Android 줄바꿈 입력도 편집 완료로 처리해 감도·PPM 입력으로 넘어가지 않게 합니다. 허용 범위 밖의 값은 오류 안내 후 편집 상태를 유지합니다. 완료 버튼과 Escape 취소도 포커스를 해제합니다.

## 최초 로딩 화면의 우선 표시

기존 로딩 div의 z-index 5000은 목록/하단 패널의 9998~10000보다 낮아 로딩 안내가 가려질 수 있었습니다. 로딩을 전체 화면 native dialog로 표시해 일반 목록·지도 오버레이의 z-index와 관계없이 앞에 오도록 수정했습니다. 로딩 중 Esc/닫힘은 막고, 완료 시 모달을 닫아 조작을 복구합니다. 기존 140 ms 지연 표시와 최소 320 ms 표시, 실패 시 재시도는 유지합니다. 로딩 진행 중 Android 뒤로가기가 배경 패널을 닫거나 앱 종료를 예약하지 않도록 했습니다.

`BearStartupReady` 완료 신호를 통해 첫 담당자/팀 설정 모달도 로딩 종료 후 열립니다. DB 초기화 실패 시에는 로딩 재시도 화면이 앞에 남으며 설정창이 가리지 않습니다. 전체 페이지에서 목록을 최대 z-index로 강제한 온라인/오프라인 테스트로 로딩 우선 표시, 목록 렌더링 완료 뒤 로딩 해제와 설정창 표시 순서를 확인했습니다. 버전은 versionCode 4 / 1.0.3-loading입니다.

## 개체 목록 전체 표시와 스크롤

개별 탐색의 개체 목록은 6개 고정 제한을 제거하고 전체 항목을 한 번에 표시합니다. 상단에 '전체 N개체', 검색 중에는 '검색 결과 N개체'를 표시하며 목록 영역 안에서 스크롤합니다. 더 보기 버튼이나 추가 로딩은 없습니다. 목록은 최대 240px(작은 화면은 화면 높이의 32%)로 제한해 수신 제어 버튼이 밀려나지 않도록 합니다. 동일한 목록을 수신 상태 갱신마다 재생성하지 않아 스크롤 위치를 보존하고, 검색어를 바꾸면 목록 맨 위에서 결과를 보여줍니다. 수신/대역 탐색 판정과 관측점 등록 연동은 유지합니다. 버전은 versionCode 3 / 1.0.2-list입니다.

## 동일 오류 재발 시 실행 파일 식별과 시작 오류 표시

재배포 후에도 registerPlugin 오류가 보고됐으나 현재 APK의 관련 호출은 모두 검사 또는 예외 처리로 보호되어 있습니다. 실제 태블릿에서 읽는 파일과 오류 위치를 확정하기 위해 앱을 versionCode 2 / `1.0.1-bridge2`로 구분합니다. 설정 하단에 빌드 버전을 표시하고, 다른 앱 코드보다 먼저 로드되는 시작 진단 코드가 처리되지 않은 오류의 메시지·스크립트 경로·줄/열 번호를 화면에 표시하며 복사할 수 있도록 했습니다. 정상 실행 중에는 오류 패널을 표시하지 않습니다. 진단은 외부로 전송하거나 위치/관측 데이터를 수집하지 않습니다.

`native-plugin-compat.js`를 다른 앱 모듈보다 먼저 로드합니다. 네이티브 런타임에 registerPlugin이 없는 경우에만 기존 `Capacitor.Plugins`의 실제 주입 객체를 찾아 반환하는 호환 함수를 제공합니다. 최신 번들 런타임의 기존 함수는 덮어쓰지 않으며 웹에는 가짜 네이티브 함수를 만들지 않습니다. 제공되지 않은 플러그인을 요청하면 명시적인 오류를 반환합니다. 이전 방식의 직접 registerPlugin 호출에 대한 회귀 테스트를 포함합니다.

MainActivity는 해당 웹 자산 revision의 첫 실행 시 WebView 리소스 캐시만 비운 뒤 한 번 초기화합니다. SQLite DB·앱 설정·관측점은 삭제하지 않습니다. Capacitor는 새 네이티브 버전을 인식해 예전 서버 자산 경로도 초기화합니다. 캐시가 현장 재발 원인이라고 단정하지 않으며, 실제 발생 파일/줄을 확인하기 위한 버전 식별과 진단을 추가한 것입니다. 원격 개체·추적·팀 API는 재배포 후 모두 200 응답으로 재확인했습니다.

## 배경지도 버튼과 Android 시작 오류

배경지도 선택 버튼은 인터넷 여부를 검사해 숨기는 기능이 아닙니다. 지도 제어 모듈 초기화 시 항상 생성하며, 오프라인 MBTiles 선택도 가능합니다. 온라인 지도 항목의 키 유무 조건만 별도로 있습니다.

순수 HTML 기반 Android 런타임은 `Capacitor.Plugins.GpsTracking`을 주입하지만 JS 번들용 `Capacitor.registerPlugin` 함수가 없을 수 있습니다. 이동 기록 UI가 이 함수를 무조건 호출해 `TypeError`가 발생하면 `client-ol.js` 실행이 지도 제어 초기화 전에 중단돼 배경지도 버튼과 후속 기능이 나타나지 않습니다. 주입된 플러그인을 우선 사용하고 registerPlugin은 존재할 때만 사용하는 방식으로 수정했습니다. 선택 기능인 이동 기록 플러그인이 없더라도 지도 초기화는 계속하도록 처리했습니다. 버튼에는 고유 ID와 '배경지도 선택' 접근성 이름을 부여했습니다.

Android와 같은 주입 방식(네이티브=true, registerPlugin 없음)으로 전체 페이지를 실행하고 외부 요청을 모두 차단해도 버튼이 표시되며 MBTiles 라디오를 선택할 수 있음을 확인했습니다. 이 검증에서 SQLite·GPS는 테스트 연결이며, 실제 단말 수신/네트워크 로그 확인을 대체하지 않습니다. 개체 목록의 원격 API 403은 앞서 설명한 별도 백엔드 반영 문제입니다.

## 실제 Spring 백엔드 연결 확인

배포 대상 `bearmap.duckdns.org`는 별도 `bear-admin` Spring 서버입니다. Node의 `/api/realtime/bear-entities` 구현만 변경하면 원격 서버에는 반영되지 않습니다. 확인 시 기존 `/api/realtime/bear-estimates`는 200이었지만 개체 주파수 목록은 모바일 보안 체인에서 403으로 차단됐습니다. `C:/workspace/bear-admin`에 모바일용 개체 주파수 컨트롤러·DTO·조회 SQL과 해당 경로 GET/CORS 허용을 추가했습니다. 앱 요청 주소와 응답 형식은 유지합니다.

새 Spring JAR을 임시 로컬 포트에서 실행해 실제 DB의 활성 52개체, 기존 개체 추적 조회, 팀 목록이 모두 200으로 응답하는지 확인했고 임시 서버는 종료했습니다. 운영 서버 배포·재시작은 수행하지 않았습니다. 이 백엔드 수정은 서버 JAR 반영이 필요하며 APK 교체만으로 원격 API의 403이 해소되지는 않습니다.

## 개체를 선택하는 개별 탐색과 기존 관측점 등록 연결

개별 탐색에서 개체 번호로만 검색하고 개체를 선택하면 해당 개체의 첫 유효 주파수를 CW 수신값으로 적용합니다. DB의 `frequency_a`, `frequency_b`, `frequency_c`를 사용하며 여러 값이 있으면 A/B/C 중 하나를 선택합니다. 주파수 없는 개체는 표시하되 선택할 수 없습니다. 등록 주파수에 1 kHz보다 작은 단위가 있어도 정수 Hz로 보존하며, 수동 주파수 입력의 기존 자릿수 UI는 유지합니다. 개체 선택을 해제하면 수동 수신을 사용할 수 있습니다. 기존 대역 탐색 알고리즘과 설정은 변경하지 않습니다.

선택 주파수에서 실제 수신 데이터가 들어오면 '비프 확인 · 관측점 등록' 버튼이 나타납니다. 사용자가 확인한 후 수신을 정지하고 SDR 모달을 닫은 다음 기존 등록창을 엽니다. 개체 번호를 자동 입력하고 잠가 다른 개체로 잘못 저장되는 것을 방지하며, 작은 출처 줄에 개체·수신 주파수를 표시합니다. 위치/방향각/명칭/담당자·팀/감지기/로컬 저장·공유는 기존 관측점 등록 기능을 사용합니다. 취소·닫기·Android 뒤로가기는 선택 개체/주파수를 유지한 SDR 화면으로 돌아가며 자동으로 소리를 재생하지 않습니다. 저장 성공 시에는 기존 목록·지도 반영 흐름을 따릅니다. 일반 목록에서 등록을 열면 SDR 출처·잠금은 해제됩니다. 이미 작성 중인 새 등록창은 입력값을 유지하고 개체·주파수만 갱신합니다. 수신 수치로 비콘이나 개체를 자동 식별하지 않습니다.

개체 조회 API에 주파수 A/B/C를 추가했고 웹의 읽기 전용 게이트웨이도 연결했습니다. 앱에는 현재 DB에서 조회한 활성 개체 주파수 목록을 포함하고 성공적으로 조회한 최신 목록을 별도로 캐시합니다. 오프라인/접근 거부/이전 서버 응답으로 갱신하지 못하면 저장 목록을 사용한다는 문구를 표시합니다. 명시적인 빈 최신 목록은 과거 목록으로 덮어쓰지 않습니다. 원격 서버 API가 주파수를 내려주려면 해당 서버에도 라우트 변경을 배포해야 합니다.

검증: 개체 검색, A/B 선택과 Hz 정밀도, 실제 수신 전 등록 불가, 수신 정지 후 동일 개체 전달, 기존 등록창 취소·저장 및 일반 등록 복귀를 자동 테스트와 320/390/844/800px 브라우저 화면으로 확인합니다. 브라우저 검증의 수신·위치·저장은 테스트용 연결이며 태블릿 USB 실기 수신은 별도 확인이 필요합니다.

## 현장 누락 보고 후 탐색 판정 원복 (현재 적용)

사용자는 잡음 후보가 3칸으로 표시되는 문제를 제기했으며 148.241 MHz 검출은 당시 동작했습니다. 이후 추가한 3회 확인·간격/폭 일관성·16 kHz 폭 제한과 좁은 CW 그룹/병합 변경을 모두 제거하고, 이 대화에서 해당 변경 이전의 검출 로직으로 복구했습니다. 완료된 짧은 펄스 2회, 펄스 최대 0.4초와 간격 0.3~4초의 기존 조건, 빈 간격 8개 및 최소 10 kHz 병합 기준, 기존 최근 관측 갱신 방식을 사용합니다. 체류 5초, 연속 FFT 분석, 기본 감지 기준 10 dB도 당시대로 유지합니다. 반복 간격·폭 추가 표시는 제거했습니다.

후보 아이콘과 정렬은 잡음 대비 기준을 유지합니다. 아이콘은 후보를 숨기거나 탐색 검출 조건을 바꾸지 않습니다. USB 목록, 고정 CW 청취, 고정 스펙트럼과 드래그 개선도 유지합니다. 회귀 테스트는 정확히 두 펄스, 중간 펄스가 누락된 경우, 펄스 폭이 달라진 경우의 148.241 MHz 후보 검출을 확인합니다. 재현 시 2초 반복 검출이 20개 시작 위상 중 10→20개로 회복됐지만, 태블릿의 실제 누락 원인과 검출 회복은 실기 확인이 필요합니다. 아래 강화/분리 절은 과거 작업 기록이며 현재 적용되지 않습니다.

## CW 비콘 옆 연속 신호에 의한 후보 누락 수정

기존 CW 탐색은 임계값 아래 FFT 빈을 8개까지 건너뛰며 주파수 덩어리를 만들고, 후보도 최소 10 kHz 이내에서 합쳤습니다. 148.241 MHz 비프 옆 8 kHz 거리의 강한 연속 반송파가 있으면 둘이 합쳐져 active 상태가 끊기지 않아 비프 후보가 사라지는 조건을 재현했습니다. CW에 한해 빈 간격 허용을 1개로, 후보 병합 거리를 최대(2 kHz, FFT 2빈)로 좁혔습니다. WFM/IQ 그룹화와 CW 반복성·폭·3회 확인 기준은 유지합니다. 5/8/10 kHz 거리의 연속 반송파 옆 비콘 검출 및 실제 FFT+합성 IQ 회귀 테스트를 추가했습니다.

148–150 MHz 계획에는 148.241 MHz를 유효하게 포함하는 구간이 2개 있어 범위 누락은 아닙니다. 약 1.12초 반복은 5초 창 내 확인되지만 잡음 대비 상승이 기본 10 dB 미만이면 여전히 제외됩니다. 이 수정은 재현된 누락 조건을 해결하며 현장 누락 원인을 확정하지는 않습니다. 태블릿에서 고정 수신 비프를 확인한 같은 상태로 148.200–148.300 MHz를 두 바퀴 탐색한 뒤 필요하면 감지 기준 10→6 dB를 비교합니다. 강한 연속 CW 음은 목표 비콘이라는 증거가 아닙니다.

## SDR 첫 진입의 USB 목록 정리

연결 전은 USB 수신기 제목·새로고침을 상단에 두고 장치별 카드에 USB 제품명, VID/PID, 연결 버튼을 배치합니다. 바깥 여백 12px와 카드 내부 10px로 버튼과 경계선 사이 공간을 확보하며 연결/새로고침은 44px 터치 높이를 유지합니다. 긴 이름은 줄바꿈하고 빈 제품명은 'RTL-SDR 수신기'로 표시합니다. 목록 정보는 Android USB 제품명과 ID이며 연결 전 튜너 성능 확인을 의미하지 않습니다. 권한 대기 중 연결 버튼은 '권한 대기'로 표시하고 비활성화합니다. 연결 후에는 기존의 장치명·상태·작은 해제 버튼 한 줄을 유지합니다. 웹에서 USB 기능을 사용할 수 없으면 빈 목록/비활성 도구 대신 Android 앱 안내만 표시합니다.

실제 전체 CSS로 320/390px 모바일, 가로, 태블릿의 장치 없음·일반·긴 이름·여러 장치·권한 대기·연결됨 24개 상태를 검증하고 스크린샷을 확인했습니다. 연결 버튼 내부 여백은 11px, 새로고침은 외곽선에서 13px 떨어져 있으며 가로 넘침이 없습니다. 연결 이후 준비/수신/음소거 화면의 배치 검사도 유지합니다.

## 탐색 후보의 잡음 기준 표시와 반복성 검증

탐색 목록의 4단계 아이콘과 정렬을 절대 dBFS에서 잡음 대비 상승량(snrDb)으로 변경했습니다. 6 dB 이하는 0단계, 이후 7.5 dB 간격으로 증가해 최대 4단계입니다. 이는 해당 탐색 FFT의 주파수별 배경 중앙값에 대한 상승량이며 고정 수신 게이지의 시간 방향 CW 잡음 추정과 측정 방법이 달라 수치가 같지는 않습니다. 원래 dBFS/bin도 함께 표시합니다.

CW 후보 승격은 이전의 완료 펄스 2회에서 같은 구간 내 완료 펄스 3회 이상으로 강화했습니다. 펄스 폭은 최대 0.4초, 간격은 0.3~4초이고 연속된 간격/폭이 비슷해야 합니다. 간격은 25% 또는 120 ms, 폭은 50% 또는 80 ms 중 큰 편을 허용하며 USB 두 블록 시간 해상도도 고려합니다. 16 kHz보다 넓게 점유한 신호는 CW 후보에서 제외합니다. 검증 뒤 목록에 반복 횟수·평균 간격·대략적인 펄스 폭을 표시합니다. 확인된 후보도 이후 단발성 잡음만으로 마지막 검증 시각/회차/전력이 갱신되지 않습니다. 과거 후보는 기존 최근 미감지 표시로 남습니다.

현재 체류 5초 안에 3회 완료되지 않는 느린 비콘은 후보에서 빠질 수 있습니다. 규칙적인 다른 간섭도 통과할 수 있으므로 이 기준은 비콘 식별/상태 판독이 아닙니다. 148.241 MHz의 실제 신호로 반복값과 후보 청취를 확인합니다. 이번 변경은 탐색 후보 표시와 판정에 한정하며 스펙트럼은 변경하지 않았습니다. 아래 과거 절의 '2회' 기준은 이 절의 3회·규칙성 확인으로 대체합니다.

## CW 고정 수신의 짧은 펄스 시각화

CW 고정 수신도 탐색처럼 모든 USB 블록의 완전한 1024쌍 FFT 프레임을 연속 분석합니다. 각 블록의 주파수별 최대 전력을 계산하고 각 빈의 피크를 250 ms 유지한 뒤 초당 36 dB씩 감쇠합니다. 이 결과를 기존 100 ms 측정 갱신에 함께 전달하므로 짧은 펄스를 다음 화면 갱신까지 유지합니다. 화면에는 '순간 피크 유지'를 표시하며 값은 순간/유지 피크 dBFS/bin이고 평균 전력이 아닙니다. 수신 시작마다 유지 기록을 초기화합니다. 이 표시는 CW 청취, 게이지 계산, 대역 탐색 판정에 영향을 주지 않습니다. 잡음과 다른 신호도 피크로 잡히므로 비콘 식별을 의미하지 않습니다. IQ/WFM의 기존 500 ms FFT 방식은 유지합니다.

검증: USB 블록의 21번째 FFT 프레임에만 존재하는 펄스 포착, 다음 100 ms 화면 갱신까지 유지, 250 ms 뒤 감쇠, 새 펄스 즉시 상승, 시작 시 잔상 초기화를 단위 테스트로 확인합니다. 실제 USB 처리 속도와 비프음/시각 반응은 태블릿에서 확인합니다. 아래 절의 500 ms 스펙트럼 설명은 변경 전 동작이며 CW는 이 절의 연속 분석 방식으로 대체합니다.

## 스펙트럼 미세 조정과 CW 청취 반응

과거에는 정지한 스펙트럼에서 가로 12 CSS px당 1 kHz씩 조절하고 다음 수신 시작에 적용했습니다. 현재 이 드래그 조절은 제거되었으며 위의 표시 전용 동작을 따릅니다.

CW 오디오는 실제 IQ를 가청 주파수로 변환하며 별도의 반복 비프음을 생성하지 않습니다. 합성 IQ 테스트로 실제 두 펄스 사이 무음, 수신 진폭에 따른 오디오 크기, 튜닝 차이에 따른 음높이 변화를 확인합니다. 스펙트럼은 500 ms 주기로 갱신하므로 짧은 비프마다 시각적으로 일치하지 않을 수 있습니다. 오디오 버퍼 요청을 200 ms에서 50 ms(기기 최소 버퍼 우선), 대기 큐를 8개에서 3개 블록으로 줄이고 넘치면 오래된 블록을 버려 지연 누적을 줄입니다. 실제 지연과 끊김 여부는 태블릿 출력 경로에서 확인해야 합니다.

모바일 크기 보완: 주파수 숫자는 정수 3자리/소수 3자리(예: 148.241)이며 화면 입력 상한은 999.999 MHz입니다. 연결 해제 버튼은 표시 높이 30px로 줄이고 위아래 투명 클릭 영역을 확보했습니다. 감도/PPM 입력 폭은 84px로 제한하고 소리 버튼은 주파수 옆 별도 그리드 칸에 고정했습니다. 실제 페이지의 전체 CSS를 함께 불러와 320/390px 모바일, 가로 및 태블릿에서 준비·수신·음소거 상태의 폭/정렬/잘림을 확인했습니다.

## CW 전용 모바일 화면 정리

사용자 화면의 수신 모드를 CW로 고정하고 수신 모드/음색 보정 선택란을 제거했습니다. 샘플레이트는 기본 1.024 MS/s, 탐색 체류는 5초로 유지하며 드롭다운 없이 감도(Gain), 주파수 보정(PPM), 탐색 감지 기준만 직접 조절합니다. 네이티브 IQ/WFM DSP 및 회귀 테스트는 유지하되 사용자 화면에서 선택하지 않습니다.

연결된 장치는 이름·연결 상태·해제 버튼 한 줄로 표시하며 연결 후 새로고침/USB 식별번호 표시와 중복 연결 상태 안내를 숨깁니다. 설정/결과/측정 정보/도움말의 접기 메뉴를 제거했습니다. 준비 상태에서는 설정을 표시하고, 수신·탐색 중에는 수정할 수 없는 설정을 숨겨 결과만 표시합니다. 정지하면 설정이 다시 나타납니다. 주파수 옆에 음소거 버튼을 두고 수신 데이터/대역 전력은 작은 한 줄 지표로, 스펙트럼은 높이 160px로 줄였습니다. 시작·정지·초기화 버튼은 해당 상태에서 필요한 것만 하단에 표시합니다. 숫자와 방향 화살표, 소수점 3자리 입력은 유지합니다.

Headless Chrome에서 320×740, 390×844, 844×390, 800×1280의 준비/수신/탐색 화면을 검증했습니다. 가로 잘림·스크립트 오류·화면 밖 하단 버튼이 없고, 모바일 세로 준비/수신 화면은 본문 스크롤 없이 표시됩니다. 실제 Android WebView/USB 실기 확인은 별도로 필요합니다.

## CW 대역 탐색 펄스 누락 개선

기존 탐색은 100 ms 간격으로 USB 블록 앞쪽 최대 4096 IQ쌍만 FFT로 분석했습니다. 기본 1.024 MS/s에서는 약 4 ms의 구간이므로 약 20 ms 비콘을 놓칠 수 있습니다. CW 탐색은 안정화 후 모든 USB 블록의 완전한 1024쌍 FFT 프레임을 연속 분석하고 각 블록의 주파수별 피크를 사용합니다. 고정 수신 스펙트럼과 IQ/WFM 탐색 분석 방식은 유지합니다.

CW 후보는 같은 수신 구간에서 짧은 on/off 펄스가 두 번 이상 끝나는지 확인합니다. USB 블록 시간 해상도를 고려해 펄스 길이는 최대 0.4초, 반복 간격은 0.3~4초로 허용합니다. 연속 스퍼와 1회성 잡음은 확인 후보로 올리지 않으며 튜닝 변경 자체가 펄스 반복으로 계산되지 않도록 구간 전환 시 미확인 펄스 기록을 초기화합니다. 이는 M3620 특성을 이용한 후보 필터이며 비콘 식별이나 상태 해독은 아닙니다.

CW 구간 체류는 5초로 고정합니다. 기본 샘플레이트에서 148–174 MHz는 약 74구간으로 한 바퀴 약 6분 25초입니다. 실기 테스트는 CW 148.200–148.300 MHz에서 148.241 MHz 부근 후보 확인 → 후보 선택 후 비프음 청취 → 148–174 MHz 확장 순서로 진행합니다. -58.3 dBFS/bin은 FFT 후보 전력이며 고정 수신 채널 전력/게이지 값과 동일한 측정값이 아닙니다.

## CW 게이지 잡음 기준 개선

CW의 기존 절대 전력 눈금을 배경 잡음 대비 상승량 기준으로 바꿨습니다. 최근 2.56초의 10 ms 전력 구간 중앙값을 배경으로 추정하고 시작 후 0.5초 이상 데이터가 쌓이면 표시합니다. 짧은 비콘 펄스가 기준을 끌어올리는 영향을 줄이도록 평균 대신 중앙값을 사용합니다. 갱신 구간의 최대 전력이 배경보다 6 dB 이상 높아질 때부터 3 dB 간격으로 막대를 채웁니다. 오디오 복조/볼륨은 바꾸지 않았으며 원래 전력 dBFS도 유지합니다. WFM은 기존 절대 전력 눈금을 유지합니다.

현재값 아래에 배경 잡음 dBFS와 잡음 대비 상승 dB를 표시합니다. 새로운 주파수/샘플레이트/Gain으로 수신을 시작할 때 기준이 초기화됩니다. 환경 잡음 변화는 약 2~3초에 걸쳐 반영됩니다. 간섭 역시 상승량에 포함될 수 있으며 CW 전파나 비콘의 존재를 확정하는 검출기는 아닙니다. 지속되는 신호는 기준에 흡수될 수 있으므로 이 기준은 M3620처럼 짧게 반복하는 비콘용입니다. 잡음 속에 묻힌 약한 비프음은 0칸에서도 들릴 수 있습니다.

검증: 여러 잡음 세기에서 잡음만으로 게이지가 채워지지 않는지, 같은 잡음 위의 약한/강한 20 ms 펄스가 구분되는지, 펄스가 사라지면 내려가는지, 잡음 수준 변화 후 다시 안정되는지 합성 IQ로 확인합니다. 태블릿에서 안테나 분리 시 배경값/상승량/막대와 실제 비프음 수신 시 변화를 비교해야 합니다.

## 수신 신호 세기 게이지

고정 수신 결과의 현재 주파수 아래에 왼쪽부터 높아지는 10개 막대를 표시합니다. CW는 선택한 신호의 필터 출력에서, WFM은 FM 복조 전 채널 필터 출력에서 전력을 측정합니다. 음량·음소거에 영향을 받지 않으며 전체 샘플 대역 전력과 구분합니다. IQ 모드에서는 채널 게이지를 표시하지 않고 CW/WFM 측정을 안내합니다.

3 ms 전력 평균을 계산하고 약 100 ms 갱신 구간의 최대값을 표시합니다. USB 블록 길이에 따라 갱신 간격은 달라지며 스펙트럼 분석 주기는 기존 500 ms를 유지합니다. 별도 장기 피크 유지나 자동 눈금 조정은 하지 않습니다. 고정 눈금 -90~−10 dBFS를 10단계로 표시하며 IC-R30의 S단위나 보정된 dBm과 동일한 눈금은 아닙니다. 방향 비교 시 주파수/수신 모드/Gain을 유지해야 합니다. 정지 시 마지막 측정임을 표시하고 초기화 시 지웁니다.

태블릿에서 CW 148.241 MHz 청취와 함께 안테나를 돌려 소리·게이지가 같은 강약 변화를 보이는지 확인하고 IC-R30과 비교합니다. 정확한 눈금 일치를 위한 실기 보정은 아직 수행하지 않았습니다.

주파수 표시/입력은 MHz 소수점 3자리이며 마지막 숫자와 화살표는 1 kHz 단위입니다. 고정 수신, 탐색 입력, 후보 목록과 복원 표시에 동일하게 적용합니다.

## 수신 대역 프리셋 제거 / CW 기본값 / 탐색 모드 선택

88–108 MHz와 140–174 MHz를 고르는 수신 대역 설정란을 제거했습니다. 기본 수신 모드는 CW이며 고정 수신과 대역 탐색에서 CW/IQ/WFM을 선택할 수 있습니다. 고정 수신은 주파수, 탐색은 시작·끝 주파수를 직접 입력합니다. 기존 숫자/화살표 디자인과 1 kHz 조정을 유지하며 1000 MHz 이상 입력을 위해 정수 자리를 하나 늘렸습니다.

앱의 숫자 처리 범위는 0.1–2000 MHz이며 실제 수신 가능 범위는 연결된 튜너와 안테나에 따라 다릅니다. 기존 방송/VHF 프리셋으로 입력을 제한하지 않으며 장치가 지원하지 않는 주파수의 튜닝 오류는 표시합니다. 탐색 중에는 오디오를 재생하지 않습니다. 선택한 모드는 탐색 검출과 후보 청취에 사용합니다. WFM은 방송형 폭·지속성 검출, CW/IQ는 일반 RF 검출을 사용하며 비콘 판정/상태 해독 기능은 아닙니다. 후보 선택 시 탐색의 모드를 유지합니다. 네이티브 탐색 상태에 모드를 저장해 화면 복원과 재개에도 적용하며 모드 변경 후에는 새 탐색을 시작합니다.

태블릿 확인: 기본 CW 및 수신 대역 선택란 제거 확인 → 고정 148.241 MHz 청취 → 탐색 CW / 148–150 MHz → 후보 선택 후 CW 청취 → WFM으로 변경 후 새 탐색 → 앱 화면 재생성 후 탐색 모드 복원 확인.

## CW 비콘 청취 추가

IC-R30의 CW 청취에 대응해 고정 수신에 CW 모드를 추가했습니다. 태블릿에서는 **주파수 고정 → CW → 148.241 MHz → 수신 시작**으로 테스트합니다. 소리는 기본 재생되며 음소거 버튼과 기기 미디어 볼륨으로 조절합니다. 기존 숫자/화살표 디자인에 1 kHz 자리를 추가했습니다. 약한 비프음이 없으면 마지막 자리로 주변 주파수를 미세 조정합니다. 잡음 출력만으로 비콘 검출을 판정하지 않습니다.

CW는 실제 IQ를 700 Hz 비트음으로 변환하고 좁은 저역 필터를 거쳐 48 kHz PCM을 출력합니다. DC 스파이크를 피하도록 하드웨어 중심은 선택 주파수보다 12 kHz 낮게 두고 복조에서 보정합니다. 스펙트럼은 실제 하드웨어 중심을, 복원된 주파수 선택은 청취 주파수를 사용합니다. 상태 해독이나 비콘 판정은 추가하지 않았습니다.

CW 청취는 실제 I/Q 신호를 혼합·필터링한 결과이며, 신호 세기가 문턱을 넘으면 별도 비프음을 재생하는 방식이 아닙니다. 수신 감도 기본 요청은 50dB로 두고 librtlsdr가 연결된 튜너의 지원 단계 중 가장 가까운 값을 적용합니다. 현재 지원 튜너의 최대값은 모두 50dB 이하이므로 기본 요청은 각 튜너의 최대 단계가 됩니다. FC0013은 최대 19.7dB, R820T/R828D는 최대 49.6dB입니다. 상세 설정의 감도 아래에 실제 인식 튜너·적용 Gain·지원 최대 Gain을 표시합니다. USB 연결 해제 후에는 기본 최대 요청으로 돌아가며, 수동 감도 조절은 기존처럼 정지 후 재시작하여 적용합니다.

검증: `node --test tests/sdr-cw.test.cjs tests/sdr-wfm.test.cjs tests/sdr-diagnostics.test.cjs tests/sdr-spectrum.test.cjs`. CW 합성 펄스의 700 Hz 출력, 펄스 사이 억제, DC 억제, 모든 샘플레이트, 홀수 USB 블록 경계, UI/오디오 제어와 1 kHz 조정을 확인합니다. 실제 M3620 및 IC-R30 비교 청취는 태블릿에서 수행해야 합니다.

## 2026-10-23: VHF 비콘 / FM 방송 테스트

대역 선택(VHF 140–174 MHz / FM 방송 88–108 MHz)과 IQ/WFM 선택을 유지합니다. 주파수 입력의 변경을 확정하거나 시작 버튼을 누르면 입력값에 맞는 대역으로 자동 전환합니다. 주파수 대역과 복조 방식은 분리되어 WFM을 선택해도 148 MHz 등 VHF 주파수를 유지합니다. Android 검증도 같은 범위를 허용합니다. 지원 대역 밖 또는 두 대역에 걸친 탐색 범위는 오류로 안내합니다. 직접 입력은 기존 화살표 사이 숫자 칸을 편집하며 별도 입력창으로 전환하지 않습니다.

태블릿 확인 순서:

1. USB 수신기를 연결하고 FM 방송 대역을 선택한 뒤 대역 탐색에 148.000–150.000 MHz를 입력합니다. VHF로 자동 전환하고 입력 범위를 유지해 탐색하는지 확인합니다. M3620 테스트는 구간 체류 2초 또는 5초로 비교합니다.
2. 주파수 고정에 실제 발신기 주파수를 입력하고 IQ 스펙트럼을 확인합니다. 후보 검출과 Activity/Mortality/Time Since Death 해독은 별개이며 상태 해독 기능은 추가하지 않았습니다.
3. WFM을 선택하고 148 MHz에서 소리 켜기/음소거와 기기 미디어 음량을 확인합니다. 이후 현지 FM 방송 주파수에서도 청취를 확인합니다. M3620의 비프음 청취 적합성은 실기로 확인하며 NFM/AM 복조는 구현하지 않았습니다.
4. 140–150 MHz 탐색은 허용하며, 139–150 MHz 또는 100–150 MHz 입력 시 지원 범위 안내가 표시되고 수신을 시작하지 않는지 확인합니다.

## Android 15 백그라운드 수신 테스트

현재 대역 탐색과 주파수 고정 수신 모두 실행 중에는 `connectedDevice` 포그라운드 서비스를 사용합니다. 설정 창을 닫거나 화면을 꺼도 수신을 유지하며, 다시 열면 네이티브 상태를 읽습니다. 앱의 **정지** 또는 실행 알림의 **정지**는 수신만 멈추고 USB 연결은 유지합니다. 설정 창을 닫아도 USB 연결은 유지하며, **연결 해제 / 취소** 또는 실제 USB 분리 시에만 연결을 해제합니다. 다만 앱 프로세스 자체가 종료되면 Android의 USB 파일 디스크립터는 유지되지 않아 다시 연결해야 합니다. 이 동작은 Android 15 실기에서 아직 검증되지 않았습니다.

대역 탐색 중 하단 오른쪽 버튼은 **일시정지**입니다. 멈추면 왼쪽은 **탐색 재개**, 오른쪽은 **초기화**로 바뀝니다. **초기화**는 후보·회차·재개 지점을 지우고 USB 연결과 수신 설정은 유지합니다. 다음 **탐색 시작**은 1회차부터 새로 시작합니다.

주파수 고정 수신 중 하단 오른쪽 버튼은 **정지**이고, 정지 후에는 **초기화**로 바뀝니다. 이 초기화는 마지막 수신량·대역 전력·스펙트럼·오류 결과만 지웁니다. 주파수·Gain 등의 설정, USB 연결, 이전 대역 탐색 기록은 유지합니다.

대역 탐색 기록이 남아 있더라도 사용자가 수신 방식에서 **주파수 고정**을 직접 선택하면 고정 화면 하단에는 **수신 시작 / 정지·초기화**만 표시합니다. 탐색 후보를 눌러 고정 수신에 들어온 경우에만 상단 **‹ 탐색**으로 이전 탐색을 이어갑니다. 이 경로는 휴대폰 뒤로가기에도 연결됩니다.

주파수 고정 수신의 스펙트럼은 사용자가 봉우리 움직임이 너무 빠르다고 보고해, 약 **500 ms**마다 측정값을 직접 표시하는 초기 방식으로 되돌렸습니다. 추가 화면 보간이나 픽셀별 봉우리 묶음을 사용하지 않습니다. 캔버스 크기가 같으면 재할당하지 않는 최적화만 유지합니다. 실제 화면 움직임은 Android 기기에서 확인합니다.

지도 상단의 SDR 버튼 아래에 현재 상태를 짧게 표시합니다. **탐색 중 / 수신 중 / 일시정지 / 수신 오류**만 보여주고, 버튼을 누르면 기존 수신기 설정 창을 엽니다. 설정 창을 닫아도 상태를 갱신하며, 앱 화면이 다시 생성되어도 네이티브 수신 상태를 읽어 복원합니다. 화면에 표시한 회차는 접근성 설명에도 포함됩니다.

Android 14 이상에서 사용자가 실행 알림을 밀어 지워도 탐색이 계속되고 알림 권한이 켜져 있으면 약 3초 뒤 같은 알림을 다시 게시합니다. 제조사별 해제 이벤트가 누락되는 경우를 위해 30초마다 알림 존재 여부를 확인합니다. 앱의 정지, 알림의 정지, USB 분리, 수신 오류, 알림 차단 시에는 복원하지 않습니다. Android의 실행 중 앱 관리 화면에서 앱 자체를 중지하면 프로세스가 종료되므로 자동 재시작하지 않습니다. Android 15 실기에서 알림 재게시 동작을 확인해야 합니다.

앱에서 USB 연결과 알림 권한을 허용한 뒤 수신을 시작하면 서비스가 수신 객체와 USB 연결을 유지합니다. 앱의 **일시정지**는 탐색 기록을 남겨 같은 연결에서 재개할 수 있습니다. 서비스 종료 시에는 CPU wake lock을 정리합니다. 실제 비콘 판정·후보 알림·진동은 이 단계에 포함되지 않습니다.

Android 15 실기 검증: FM 103.000–104.000 MHz에서 탐색을 시작하고 설정 창을 닫은 뒤 화면을 5분간 끕니다. 알림이 유지되는지 확인하고 앱으로 복귀해 **회차 증가와 후보 유지**를 확인합니다. 이어 앱 전환, 알림의 정지, USB 분리를 각각 시험합니다. 실제 화면 꺼짐 수신 지속과 발열·배터리 소모는 아직 기기에서 검증되지 않았습니다.

### 대역 탐색 사용과 검증

수신기 설정 창의 뒤로가기는 수신음 화면에서 탐색 목록으로 복귀하거나 설정 창을 닫습니다. 창 안에서는 앱 종료를 대기하지 않습니다. 설정 창을 열 때 기존 지도 종료 안내와 대기 타이머를 취소합니다. 지도에서 뒤로가기를 누르면 종료 안내가 2초 동안 표시되며, 그동안 다시 누르면 종료합니다. 안내가 사라지면 종료 대기도 해제됩니다. 이 경로를 포함한 UI/스펙트럼 테스트 39개가 통과했습니다.

#### FM 방송 테스트의 잡음 후보 억제

FM 대역 탐색에만 별도 스펙트럼 필터를 적용합니다. 각 구간에서 서로 다른 시점의 FFT 관측 **4개를 선형 전력으로 평균**하고, 최소 **0.25초** 동안 이력을 모읍니다. 평균 스펙트럼의 최대값은 기존 감지 기준(기본 주변 잡음 대비 **+10 dB**)을 넘어야 합니다. 폭 판정에는 `max(6, 감지 기준−4)` dB를 쓰고, 각 주파수 칸이 **4개 관측 중 3개 이상** 이 기준을 넘는지 확인합니다. 점유 폭 **30 kHz 이상**, 전체 묶음 폭 **300 kHz 이하**, 점유 비율 **35% 이상**인 신호만 후보 관측으로 인정합니다. 그런 관측이 두 번 있어야 목록에 표시합니다. 구간 재조정마다 평균 이력을 초기화합니다.

이는 순간 잡음·좁은 스퓨리어스·과도하게 넓은 전력 상승을 억제하는 **방송 형태의 후보 필터**입니다. WFM 음성의 내용이나 복조 후 잡음, 스테레오 파일럿, RDS를 검증하지 않으므로 실제 방송을 확정하는 기능은 아닙니다. 지속적인 넓은 간섭은 통과할 수 있고, 약하거나 변조가 작은 방송은 누락될 수 있습니다. VHF 비콘은 좁고 간헐적인 신호일 수 있어 이 FM 필터를 적용하지 않습니다.

실기 비교는 **FM 방송 → 대역 탐색 → 103.000–104.000 MHz**, 샘플레이트 **1.024 MS/s**, Gain **10 dB**, PPM **0**, 체류 **1초**, 감지 기준 **10 dB**로 시작합니다. 먼저 고정 WFM에서 103.5 MHz의 방송 청취 여부를 확인한 다음 탐색 후보에 같은 방송이 남는지 확인합니다. 후보를 눌러 듣고 잡음만 들리는 항목이 줄었는지 비교합니다. 103.5 MHz가 누락되면 체류를 **2초**로 늘려 재시험하고 안테나·Gain·샘플레이트는 유지합니다. 방송 확인에는 넓은 대역 재탐색보다 이 작은 범위 비교가 먼저입니다.

선택한 범위를 반복 탐색하는 동안 새 후보를 자동으로 추가합니다. **현재 또는 직전 회차에서 감지된 후보를 먼저**, 그 안에서는 **마지막 측정 dBFS/bin이 높은 순서**로 정렬합니다(동률이면 주파수순). 두 회차 이상 다시 감지되지 않은 후보는 아래로 내려 회색으로 표시합니다. 실제 전력값을 시간에 따라 임의로 낮추지 않습니다. 처음 후보로 확인된 회차에는 **새 신호** 표시가 붙습니다. 정지 후에는 마지막 측정값으로 표시하며, 새 신호가 생겨도 수신 주파수를 자동으로 바꾸지 않습니다.

주파수 옆에는 와이파이 모양의 **4단계 상대 세기** 아이콘을 표시합니다. 앱 표시 기준은 −70 / −55 / −40 dBFS/bin이며, 각각 이상이면 2 / 3 / 4단계입니다. 이 기준은 임시 시각화 척도이며 보정된 RSSI·거리·통신 품질이 아닙니다. Gain·샘플레이트가 달라지면 비교할 수 없습니다. 새 신호는 해당 구간을 다시 방문할 때 감지하므로 전체 범위를 동시에 관측하는 방식은 아닙니다.

기존 수신 설정에서 **대역 탐색 / 주파수 고정**을 선택합니다. 시작 버튼은 **탐색 시작 / 탐색 재개 / 수신 시작**으로, 탐색 중에는 **탐색 중**으로 바뀝니다. USB와 고급 설정은 공통입니다.

1. USB 장치 연결 후 **대역 탐색**, **FM 방송**을 선택합니다.
2. 첫 테스트는 **103.000–104.000 MHz**, 샘플레이트 **1.024 MS/s**, Gain **10 dB**, PPM **0**을 권장합니다.
3. **탐색 시작** 후 구간·회차가 갱신되고 103.5 MHz 부근 신호가 후보에 나타나는지 확인합니다.
4. 후보를 누르면 탐색 기록을 보존하며 일시정지하고 해당 주파수에 고정합니다. FM은 WFM 음성이 자동 재생되고 VHF는 IQ 분석으로 연결됩니다.
5. 고정 수신 중에는 다른 주파수를 탐색하지 않습니다. **탐색 재개**는 이전 범위·샘플레이트·Gain·PPM·체류·감지 기준을 복원하여 **중단된 구간·회차부터 이어갑니다**. 후보 목록과 ID, 마지막 측정값·시간, 누적 데이터량을 유지합니다. 수신음을 정지한 뒤 재개해도 같습니다.
6. 탐색 화면의 **일시정지**는 USB 수신을 멈추고 기록을 보존합니다. 설정이 같으면 시작 버튼이 **탐색 재개**로 바뀝니다. 범위·대역·샘플레이트·Gain·PPM·체류·감지 기준을 변경하면 **탐색 시작**으로 바뀌고 새 세션으로 초기화합니다. USB 분리·연결 해제·창 닫기는 기록을 초기화합니다. 앱 이탈은 수신을 정지하되 같은 USB 연결이 유지되면 복귀 후 수동으로 재개할 수 있습니다. 탐색 중에는 음성을 재생하지 않습니다.

재개 시 네이티브 핸들을 다시 열고 중단된 구간의 200 ms 안정화·체류 관측을 처음부터 수행합니다. 이미 완료한 구간은 반복하지 않으며 마지막 구간 완료 시 다음 회차로 넘어갑니다. FM 평균 이력은 재조정 때 비우지만 확인된 후보 목록은 유지합니다. 마지막 감지 시간은 같은 세션의 단조 시계를 계속 쓰므로 청취·일시정지 기간도 재개 후 경과 시간에 포함됩니다. 이력은 메모리에만 보관하며 앱 프로세스 재시작 뒤에는 이어갈 수 없습니다.

후보 청취 화면에서 **휴대폰 뒤로가기** 또는 상단 **‹**는 수신음을 멈추고 탐색을 재개하며 목록으로 돌아갑니다. 앱의 기존 Capacitor App 뒤로가기 처리에서 SDR 화면을 먼저 확인하므로 지도 메뉴 닫기·앱 종료가 동시에 실행되지 않습니다. 탐색 화면에서 뒤로가기는 팝업을 닫고 USB 연결·이력을 정리합니다. 직접 입력 중에는 먼저 입력 편집을 나가고, 수신 전이라면 편집 전 값으로 복원합니다. 브라우저의 dialog 취소(Escape)도 같은 경로를 사용합니다. 중복 뒤로가기와 재개 중 닫기·연결 해제는 중복 수신을 시작하지 않습니다.

팝업은 최대 **800px** 높이로 줄이고 시스템 영역 밖에 위·아래 **20px** 여백을 둡니다. Android에서 실제로 WebView와 겹치는 상태바·내비게이션·화면 잘림 영역만 CSS 픽셀로 전달하며, 이미 시스템 영역을 제외한 WebView에는 같은 여백을 다시 더하지 않습니다. CSS safe-area와 네이티브 여백 중 큰 값을 쓰고 화면 회전·키보드에 따른 visualViewport 변화에도 높이를 갱신합니다. 내용은 내부에서 스크롤하며 헤더와 하단 버튼을 유지합니다.

구간은 샘플레이트의 **35% 이하 간격**으로 겹쳐 배치합니다. 분석에는 중심 DC 주변과 바깥쪽 약 10%씩을 제외하여 이웃 구간이 빈 부분을 보완합니다. 최소 범위 폭은 **100 kHz**입니다. 요청 샘플레이트로 구간을 계획하고 실제 하드웨어 샘플레이트로 FFT 주파수를 계산합니다.
재조정 시 USB 버퍼를 초기화하고 **200 ms** 동안 데이터를 버린 뒤 구간별 **1초**를 관측합니다. 고급 설정에서 체류 **0.5 / 1 / 2 / 5초**, 감지 기준 **6–30 dB**를 변경할 수 있습니다. 예상 한 바퀴 시간에는 체류와 안정화 시간이 포함되며 USB·튜너 지연은 추가될 수 있습니다.

FFT는 약 **100 ms** 간격으로 최대 4프레임을 분석합니다. 유효 구간 전력의 중앙값을 잡음 기준으로 삼습니다. VHF는 기본 **+10 dB** 이상 신호를 묶고 서로 다른 FFT 관측에서 **2회 이상** 보이면 일반 신호 후보로 표시합니다. FM은 위 시간 평균·폭·지속성 필터를 거쳐 **FM 방송 후보**로 표시합니다. 어느 쪽도 반복 펄스나 비콘 판정을 뜻하지 않습니다.
FM 후보는 **100 kHz**, VHF는 **10 kHz 또는 FFT 4칸 중 큰 값** 이내에서 중복을 병합합니다. 가까운 서로 다른 신호가 합쳐지거나 넓은 변조 신호가 나뉠 수 있습니다. FM은 점유 대역의 중간, VHF는 에너지 가중 중심으로 후보 주파수를 추정하고 입력 화면에서는 1 kHz 단위로 표시·고정합니다. 후보는 최대 **100개**이며 마지막 감지 시각을 표시합니다. 목록이 가득 차면 미확인 또는 3회차 이상 감지되지 않은 가장 오래된 항목을 교체하여 새 신호를 수용합니다.
전력은 FFT 최대 칸의 **dBFS/bin**, 잡음 대비 값은 해당 관측 구간의 상대값입니다. 절대 수신 전력·거리·방위각으로 해석하지 않습니다. Gain/PPM/샘플레이트는 탐색 중 유지합니다. 튜너가 지원하는 실제 Gain으로 적용됩니다.

짧은 펄스는 FFT 표본 추출 사이 또는 다른 구간을 탐색하는 동안 놓칠 수 있습니다. 펄스 검출·로컬 알림·백그라운드 수신·후보 저장은 다음 단계입니다. 이번 변경은 자동 테스트와 모의 신호 화면 검증 후 APK로 제공하며, 실제 동글의 반복 재조정·감지 성능은 위 실기 절차로 확인해야 합니다.

네이티브 `stopReception()`은 수신 루프와 네이티브 핸들 정리가 끝난 뒤 응답합니다. 후보 선택·탐색 재개는 그 응답을 기다려 USB 중복 접근을 방지합니다. 정리 도중 창 닫기·연결 해제가 발생하면 다시 시작하지 않습니다.

### 주파수 조정

수신 주파수는 각 숫자의 ▲/▼로 해당 자릿수만큼 올리거나 내립니다. 최소 간격은 **0.001 MHz(1 kHz)**이며 자리올림·자리내림을 처리합니다. 선택한 대역을 벗어나는 버튼은 비활성화됩니다.
**직접 입력**을 누르면 숫자 입력으로 전환되고, **완료** 또는 Enter로 돌아옵니다. 수신 중에는 변경할 수 없으며 정지 후 조정합니다.

### 화면 문구 정리

USB 영역은 **USB 장치**라는 접이식 목록으로 표시합니다. 장치는 테두리가 있는 카드로 구분하고, 연결 전에는 **연결** 버튼을 제공합니다. 연결 후에는 버튼 대신 녹색 **연결됨** 배지를 표시합니다. 새로고침·연결 해제는 목록 아래의 보조 버튼입니다.

WFM은 새 수신을 시작하여 IQ 데이터가 확인되면 기본으로 음성을 켭니다. 사용자는 수신 결과의 **음소거** 버튼으로 끌 수 있습니다. 음소거·오디오 포커스 상실·출력 장치 분리 후에는 측정 갱신만으로 소리를 다시 켜지 않습니다. 출력 사용이 거부되면 RF 수신은 유지하고 오디오 오류를 표시합니다. IQ 모드는 음성을 켜지 않습니다.

기본 화면은 연결 상태·설정 입력·수신량/전력·수신음 버튼·스펙트럼 중심으로 구성한다.
반복적인 연결/수신 안내와 하단 설명을 제거하고, 설정값 해설과 비콘 미검증·앱 이탈 시 정지 안내는 접힌 **도움말**에 둔다.
샘플레이트에 따른 수신 구간/데이터량은 **고급 설정**, 실제 적용 설정·누적량·포화율·FFT 구간/간격은 **측정 정보**에 둔다.
스펙트럼 아래에는 수신/정지 상태와 최대 지점 값만 짧게 표시한다. 오류와 출력 장치 분리 안내는 유지한다.

### 화면과 사용 순서

1. 지도 오른쪽 위 배경지도 버튼 왼쪽 **SDR** 버튼을 누른다.
2. **USB 장치**에서 RTL2832U의 **연결**을 누르고, 권한이 없으면 Android 허용 창에서 승인한다. 승인 후 자동 연결되며 목록이 접힌다. 이미 권한이 있으면 **연결** 한 번으로 연결한다.
3. 방송 음성 테스트는 수신 대역 **FM 방송**, 수신 모드 **WFM**을 선택한다. FM 기본 주파수는 **103.500 MHz**이며, 초기 기본값은 샘플레이트 **1.024 MS/s**, Gain 요청 **10 dB**, PPM **0**, 디엠퍼시스 **75 µs**다. 테스트 설정 적용 버튼은 제거했다. 대역·모드 선택은 사용자가 바꾼 고급 설정을 초기화하지 않는다.
4. **수신 시작**을 누르면 WFM 수신음이 자동으로 켜진다. 수신 결과의 **음소거**로 끄고 **소리 켜기**로 다시 켠다. IQ 모드에는 수신음이 없다.
5. 설정을 바꾸려면 정지 후 다시 시작한다.

USB 권한과 연결은 화면에서 한 번의 동작으로 진행한다. 내부에서는 권한 요청 완료 후 `openDevice()`를 순서대로 호출한다.
목록에는 RTL-SDR 후보만 표시하며 USB LAN·오디오 등 다른 장치는 숨긴다. 현재 후보 기준은 VID `0BDA`, PID `2832` 또는 `2838`이다. 다른 제품이 이 USB ID로 인식돼도 튜너 초기화·IQ 수신 성공까지 확인해야 실제 호환을 판단할 수 있다. 다른 USB ID는 현재 후보 목록에 포함하지 않는다.
권한 거부·취소·분리 시 연결하지 않으며, 창을 닫거나 요청을 취소한 뒤 늦게 승인 응답이 와도 다시 연결하지 않는다.
연결 실패 시 오류를 표시하고, 이미 받은 권한은 다시 요청하지 않고 연결만 재시도할 수 있다. RF 수신은 여전히 **수신 시작**으로 따로 실행한다.
이 연결 흐름 변경은 UI/스펙트럼 테스트 **19개**로 확인했다(자동 연결, 연결 실패 후 재시도, 창 닫기 후 늦은 승인, 거부·취소 포함). Android 실기기 권한 창의 승인 후 자동 연결은 새 APK에서 확인한다.

이어폰은 Android에서 먼저 연결하고 **미디어 출력**으로 선택한다. 앱은 Android의 미디어 출력 경로를 사용하며 Bluetooth 장치 선택/페어링은 앱 밖에서 한다.
앱의 음량 슬라이더는 제거했으며 별도 감쇠 없이 재생한다. 음량은 휴대폰의 Android 미디어 볼륨으로 조절한다. Bluetooth·유선 등의 현재 출력 장치가 분리되거나 오디오 포커스를 잃으면 음소거한다. 다시 켜려면 출력 상태를 확인하고 버튼을 누른다.
수신 시작·정지는 스크롤되지 않는 하단 제어부에 있다. WFM 소리 켜기/음소거와 출력 상태는 **수신 결과의 수신 데이터·대역 전력 바로 아래** 수신음 패널에 있다. 좁은 화면에서도 측정값 두 칸의 폭을 유지하도록 음성 제어를 별도 행에 배치했다. USB 목록은 연결 후 접히고, 샘플레이트/Gain/PPM/음색 보정은 **고급 설정**에 들어 있다.
USB 연결·수신 설정·수신 결과는 모두 접고 펼칠 수 있다. 처음에는 수신 설정이 펼쳐져 있고 수신 결과는 접혀 있다.
새로운 수신이 시작되면 설정을 접고 결과를 펼쳐 해당 영역으로 이동한다. 이후 사용자가 접은 결과를 매 갱신마다 강제로 펼치지 않는다.
소리 켜기 버튼은 청록색, 재생 중 표시되는 음소거 버튼은 주황색이다. 버튼 문구와 눌림 상태도 함께 바뀐다.
설정 자체는 연결 전에도 준비할 수 있지만 수신 시작은 USB 연결 완료 후 가능하다.

**수신 주파수** 입력 하나로 IQ 수신 중심과 WFM 복조 주파수를 동일하게 설정한다.
FM 대역의 기본 주파수는 **103.500 MHz**다. 중심/듣기 주파수를 따로 맞추지 않는다.
WFM에 필요한 채널 여유 검증은 유지하며, 같은 중심 주파수에서는 모든 샘플레이트 프리셋을 사용할 수 있다. 첫 테스트는 **1.024 MS/s**를 권장한다.
중심에서 복조하므로 동글의 중심 DC 성분이 음질에 영향을 줄 가능성은 실기기에서 확인한다.

허용 대역: VHF 테스트 **140–174 MHz**, FM 방송 테스트 **88–108 MHz**.
FM을 처음 선택하면 사용자 시험 방송인 **103.500 MHz**로 맞춘다. 각 대역의 입력값은 현재 앱 세션에서 따로 기억한다.
수신 대역은 입력 범위 선택이며, **수신 모드**에서 IQ 분석/WFM을 따로 선택한다. WFM은 두 대역에서 허용하며 모드 변경 시 주파수는 유지한다. IQ는 오디오를 출력하지 않는다.
샘플레이트는 **0.250 / 1.024 / 1.536 / 2.048 / 2.400 MS/s**, 기본값은 **1.024**를 유지한다.
Gain 요청 −10–50 dB, PPM −100–100.
기본 **150 MHz는 임의의 테스트 값**이며 실제 발신 주파수를 뜻하지 않는다.
RTL·튜너 AGC는 끄고, 요청 Gain에 가장 가까운 튜너 지원 값을 적용하여 표시한다.
입력은 현재 앱 세션에서 유지되며 앱 재실행 시 기본값으로 돌아온다.

결과: 튜너 이름, 실제 주파수/샘플레이트/Gain, PPM, MB/s, 누적 MB, 시간, 대역 전력 dBFS, 포화율, **주파수별 전력 스펙트럼**.
1.024 MS/s에서는 약 **2.048 MB/s**, 2.048 MS/s에서는 약 **4.096 MB/s**가 기대된다(십진 MB).
103.5 MHz / 1.024 MS/s의 이론적 수신 구간은 **102.988–104.012 MHz**다.
화면에 중심 주파수 ± 샘플레이트/2의 이론적 구간과 샘플레이트 × 2 byte의 예상 수신량을 표시한다.
실제 활용 대역은 필터·가장자리 특성으로 더 좁을 수 있다. 설정 대역 경계에서도 표시 구간은 원래 값 그대로 보여준다.
FM 테스트는 우선 기본 1.024 MS/s로 진행한다. 2.400 MS/s는 약 2.4 MHz 폭 / 4.8 MB/s이며,
더 넓게 받는 대신 USB·처리 부담이 늘어난다. 100–105 MHz 전체를 한 번에 수신하지는 못한다.
샘플레이트가 다르면 잡음과 포함 신호도 달라지므로 대역 전력 비교 시 Gain과 샘플레이트를 고정한다.
공식 librtlsdr 헤더는 225001–300000 / 900001–3200000 Hz를 허용하지만,
2.4 MS/s 초과에서 샘플 손실을 예상한다고 명시한다. 이번 UI는 지원 구간 안의 5개 프리셋으로 제한한다.
관련 근거: `android/app/src/main/cpp/third_party/rtl-sdr/include/rtl-sdr.h`의 `rtlsdr_set_sample_rate` 주석.
원시 unsigned 8-bit I/Q 성분을 `(x−127.5)/127.5`로 정규화하고 평균 제곱의 `10 log10`을 표시한다.
포화율은 값이 0 또는 255인 성분의 비율이다.

**USB 연결 성공, IQ 스트림 성공, 실제 비콘 확인은 별개다.**
IQ에는 잡음도 포함된다. 대역 전력에는 중심 DC와 다른 신호도 포함되므로 특정 비콘의 세기나 dBm이 아니다.
Gain·샘플레이트·안테나 조건이 다른 수치를 직접 비교하지 않는다.
WFM 모노 복조와 오디오 재생을 추가했다. 스테레오/RDS, 다른 복조 모드, 비콘·펄스 판정, 대역 탐색, 백그라운드 서비스, 관측 저장은 아직 없다.
이번 동기 읽기 진단은 장시간 무손실 캡처를 보증하지 않는다.

### 스펙트럼 사용법과 계산

- **03 · 수신 결과** 아래 그래프에서 가로축 MHz / 세로축 dBFS/bin을 확인한다.
- 예: 103.5 MHz / 1.024 MS/s라면 102.988–104.012 MHz를 표시한다. 중심 점선은 103.5 MHz다.
- 주변보다 높거나 넓게 솟는 부분은 해당 주파수 부근의 에너지를 보여준다. 이것만으로 방송·비콘 종류가 판정되지는 않는다.
- 중심의 가는 봉우리는 동글 DC 성분일 수 있다. 그래프에는 그대로 표시하되 최대 지점 표시에서는 중심 ±3 FFT bin과 양 끝 5%를 제외한다.
- 정지 또는 오류 시 마지막 그래프임을 표시한다. 새 수신 시작·USB 해제 후에는 이전 그래프를 지운다.
- 고정 세로축은 **−120–0 dBFS/bin**이다. 위의 대역 전체 전력과는 계산 대상이 달라 수치가 같지 않다. 실제 dBm으로 보정한 값도 아니다.
- 1024-point complex FFT, periodic Hann window, 최대 4개 연속 프레임의 **선형 전력 평균**을 사용한다.
  bin 간격은 실제 적용 샘플레이트 / 1024다(1.024 MS/s에서 1000 Hz).
- FFT 전력은 `|FFT(window × IQ)|² / (2 × sum(window)²)`를 프레임 평균한 뒤 `10 log10`하고 −120–0으로 제한한다.
  이는 기존 I/Q 성분별 full-scale 기준에 맞춘 톤 전력 표시이며, Hann 주엽·잡음 대역폭을 포함한 정확한 PSD/dBm 계측은 아니다.
- raw unsigned 8-bit IQ 중 최대 8192성분(4×1024 I/Q쌍)을 약 500 ms마다 JNI에서 Java 작업 스레드로 전달한다.
  `SdrSpectrum`에서 계산하며 JS에는 **1024개 전력 값과 실제 적용 주파수·샘플레이트**만 전달한다.
- 전 구간을 연속 FFT로 처리하는 것은 아니다. 짧은 비콘 펄스는 스냅샷 사이에서 놓칠 수 있으며 향후 펄스 검출은 별도로 구현한다.
- 추가 FFT 처리의 실제 기기 처리량·발열 영향은 확인 대상이다. 첫 테스트는 기존 1.024 MS/s / Gain 10 / PPM 0을 유지한다.

### 네이티브 구현과 수명 관리

`RtlSdrPlugin` → `SdrReceiver` 작업 스레드 → `SdrNative` JNI → librtlsdr → libusb.

- 별도 드라이버 앱 없이 Android 승인 fd를 `libusb_wrap_sys_device()`에 전달한다.
- libusb context는 `NO_DEVICE_DISCOVERY`로 생성한다.
- 초기화·읽기·네이티브 해제는 단일 작업 스레드가 담당한다.
- 정지·분리 시 세대 토큰으로 이전 결과를 무효화한다. native close 후 Java fd를 닫는다.
- bulk 읽기는 250 ms 제한이며 3초간 데이터가 없으면 오류로 종료한다.
  초기화·해제 제어 전송에는 upstream timeout이 적용되어 전체 정지가 250 ms 안에 끝난다는 보장은 없다.
- IQ 원본과 fd는 JS에 전달하지 않고 약 500 ms마다 집계 수치만 전달한다.
- 창 닫기는 수신·USB 연결을 해제한다. 앱 일시중지/화면 꺼짐은 수신을 정지하며 자동 재시작하지 않는다.

### WFM 처리와 확장 구조

JNI의 복조기 생성 함수는 모드 이름으로 처리기를 생성한다. 현재 구현은 `wfm` 한 가지이며 `iq`에서는 복조기를 생성하지 않는다.
앞으로 NFM/AM/USB/CW를 추가할 때 USB 권한·IQ 수집·스펙트럼 경로를 재사용하고, 모드에 맞는 복조기와 설정 검증/UI를 추가한다. 아직 구현하지 않은 모드를 선택지에 노출하지 않는다.

`wfm_demod.h`는 직접 구현한 상태 유지 DSP다. 주파수 이동 → 100 kHz 저역 FIR/데시메이션 → 위상 차 FM 복조 → 15 kHz 오디오 FIR/분수 리샘플링 → 50/75 µs 디엠퍼시스 → DC 제거 → 모노 48 kHz PCM16 순서다.
첫 IQ 블록의 실제 샘플레이트를 확인한 뒤 복조기를 초기화한다. 이후 블록에서 PCM을 생성하므로 시작 직후 첫 블록은 음성으로 출력하지 않는다.
필터·발진기·이전 위상·홀수 바이트 상태를 USB 블록 사이에서 유지한다. 스테레오 부반송파와 RDS를 해석하지 않는다.
PCM은 JS를 거치지 않고 `SdrAudioOutput`의 별도 스레드에서 `AudioTrack`으로 재생한다. 오디오 큐는 최대 8개 블록이며, 넘치면 블록을 버리고 누락 횟수를 표시해 USB 읽기를 막지 않는다.
Media AudioFocus를 요청하며 소리 켜기는 WFM 수신 중에만 가능하다. 별도 드라이버 앱·마이크 권한·Bluetooth 페어링 제어를 추가하지 않았다.
정지·오류·USB 분리·창 닫기·앱 일시중지는 음성 출력도 멈춘다. 높은 샘플레이트의 처리량·발열과 Bluetooth 지연은 실제 기기에서 확인해야 한다.

WFM 자체에는 새 외부 DSP 라이브러리를 추가하지 않았다. 기존 libusb/librtlsdr의 라이선스와 보관·배포 조건은 그대로 적용한다.

### 이번 WFM 검증

- Node 테스트 **21개**: USB 권한/브리지, 설정 경계, 스펙트럼, WFM 단일 주파수 프리셋/음소거/기기 볼륨 사용/설정 검증, C++ 복조 테스트.
- 복조 테스트 **4개**는 APK에 들어가는 동일 C++ 헤더를 NDK Clang으로 WASM 빌드해 실행한다. 5개 샘플레이트의 합성 FM 1 kHz 톤 복원과 48 kHz 출력 수, 음·양 주파수 이동, 홀수 USB 블록 경계의 동일 결과, 50/75 µs 고음 감쇠와 잘못된 설정 거부를 확인한다.
- 이 테스트는 NDK 26.1.10909125의 Windows Clang/LLD를 사용한다. 다른 위치는 `SDR_TEST_CLANG`으로 `clang++.exe`를 지정한다. 임시 WASM 파일은 OS 임시 디렉터리에 생성되며 APK에는 포함되지 않는다.
- Android 단위 테스트 **7개**: 주파수/샘플레이트/WFM 채널 경계 3개, FFT 4개.
- `assembleDebug`, `testDebugUnitTest`, `lintDebug` 성공. Chrome의 390 px 폭 모의 화면에서 프리셋, 설정 잠금, 소리/출력 상태 및 고정 하단 제어부를 확인했다.
- **실제 WFM 방송 청취·Bluetooth 출력은 미검증**이다. ADB 기기가 연결되지 않아 새 APK의 하드웨어 동작을 대신 확인할 수 없다.

실기기에서는 방송이 들리는지, 방송 주파수를 바꾸면 수신음이 바뀌는지, 정지/재시작과 창 닫기 후 소리가 멈추는지, Bluetooth 분리 후 자동 음소거되는지 확인한다. 재생이 끊기면 오디오 누락 횟수, 수신량, 샘플레이트, 오류 내용을 함께 기록한다.
소리가 안 나오면 먼저 앱의 소리 켜기, Android 미디어 음량·출력 경로, 안테나 및 해당 지역 방송 수신 여부를 확인한다. IQ 수신량이 증가하는 것만으로 FM 방송을 정상 복조했다고 판단하지 않는다.

주요 추가 파일: `SdrReceiver.java`, `SdrNative.java`, `SdrSettings.java`, `SdrSpectrum.java`, `android/app/src/main/cpp/sdr_jni.cpp`, `CMakeLists.txt`, `public/js/sdr/spectrum.js`.
JS와 Android 모두 대역에 따른 주파수 경계와 샘플레이트 프리셋을 검증한다. 두 대역 사이의 임의 주파수는 허용하지 않는다.

## 이번 단계의 범위

이 단계는 Android USB Host 장치 조회, 접근 권한, `openDevice()` 연결 확인만 수행한다.
튜너 초기화, IQ 수집, 주파수 설정, RF 수신, 오디오, 대역 탐색은 아직 구현하지 않았다.
USB 연결 성공을 비콘 수신 성공으로 해석하면 안 된다.

## 구현

- `android/app/src/main/java/com/bearpoint/app/RtlSdrPlugin.java`: 앱 내부 Capacitor Java 플러그인.
- `public/js/sdr/diagnostics.js`, `public/css/sdr-diagnostics.css`: 지도 우측 상단 **배경지도 선택 버튼 왼쪽의 SDR 버튼**에서 여는 진단 창.
- Android 기본 USB API만 사용한다. 별도 드라이버 앱, 루팅, 추가 npm 라이브러리는 필요 없다.
- 초기 허용 USB ID: `0BDA:2832`, `0BDA:2838`. 다른 USB 장치는 표시하되 접근 버튼은 비활성화한다.
- USB ID는 RTL-SDR 후보 판단용이다. 실제 튜너는 미확인으로 표시한다.
- 모든 USB 상태 변경은 메인 스레드에서 직렬 처리한다. 권한 요청은 한 번에 하나, 90초 제한이다.
- 고유 PendingIntent URI로 늦게 도착한 이전 권한 응답을 배제한다.
- 권한 결과 필터에는 `bearpoint-usb` URI 스킴을 등록한다. URI 없는 USB 연결·분리 이벤트는 별도 필터로 수신한다.
- 앱 복귀, 상태 조회, 시간초과 직전에 실제 USB 권한을 재확인한다. 이미 승인된 요청은 대기 상태를 종료한다.
- 분리, 취소, 종료 시 대기 요청과 연결을 정리한다. 재연결 시 권한을 다시 확인한다.
- JavaScript에 USB 파일 디스크립터를 노출하지 않는다. USB 인터페이스 claim 및 RF 초기화는 다음 단계에 맡긴다.
- 진단 창을 닫으면 연결을 해제한다. 이 단계는 백그라운드 수신 서비스가 아니다.
- 장치 연결 시 앱 자동 실행은 추가하지 않았다. 앱 실행 후 목록 조회 또는 새로고침을 사용한다.

## API

현재처럼 일반 HTML/JS를 사용하는 앱은 Android가 주입한 `window.Capacitor.Plugins.RtlSdr`로 접근한다.
별도 JS 런타임이 제공하는 `registerPlugin()`은 함수가 실제로 있을 때만 대체 경로로 사용한다.

| 메서드 | 반환 / 동작 |
| --- | --- |
| `getStatus()` / `listDevices()` | `hostSupported`, `state`, `devices`, `connectedDeviceId`, `lastError`, `rfReady:false` |
| `requestDevicePermission({deviceId})` | 권한 승인 후 장치 정보 반환. 거부·시간초과·분리 시 reject |
| `openDevice({deviceId})` | 승인된 지원 장치를 열고 상태 반환. 권한 자동 요청 없음 |
| `closeDevice()` | 대기 요청 취소 및 연결 해제. 반복 호출 가능 |
| `addListener("usbStateChanged", callback)` | 연결·분리·권한 변화·앱 복귀 시 상태 전달 |

`deviceId`는 현재 연결에서만 유효한 Android 장치 경로다. DB에 영구 식별자로 저장하지 않는다.
장치 목록에는 `name`, `vendorId`, `productId`, `candidate`, `hasPermission`, `connected`, `tuner:"unverified"`가 포함된다.

## 빌드 및 연결

프로젝트 루트에서:

```powershell
npx cap copy android
cd android
.\gradlew.bat :app:assembleDebug :app:lintDebug --no-daemon
```

APK: `android/app/build/outputs/apk/debug/BearMap.apk`.
빌드 도구는 SDK 35 및 Java 21 조합을 위해 AGP 8.6.1 / Gradle 8.7로 맞췄다.
기존 `org.gradle.java.home` 경로가 없는 개발 PC는 자신의 JDK 21 경로를 설정해야 한다.

실물 연결:

```text
개발 PC <-- 무선 ADB --> Android 휴대폰
                             |
                            OTG
                             |
                          RTL-SDR
```

PC를 호스트로 한 허브에 휴대폰과 SDR을 함께 꽂으면 휴대폰의 USB Host 검증이 되지 않는다.
USB 권한 확인에는 안테나나 실제 발신기가 필요하지 않다.
휴대폰의 USB 디버깅 승인과 앱의 SDR 접근 승인은 서로 다른 권한이다.
APK 재설치에는 기존 데이터 보존을 위해 `adb install -r`을 사용하며 앱 삭제나 데이터 초기화는 하지 않는다.

## 실기기 검증표

UI 비동기 흐름 자동 검증: `node --test tests/sdr-diagnostics.test.cjs`.

테스트 컴파일은 `android` 폴더에서 `.\gradlew.bat :app:compileDebugAndroidTestJavaWithJavac`로 확인한다.
실제 실행은 연결된 테스트 기기/에뮬레이터에서 아래 명령을 사용한다(테스트 실행 과정에서 앱과 테스트 APK를 설치함).

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest "-Pandroid.testInstrumentationRunnerArguments.class=com.bearpoint.app.RtlUsbIntentFilterTest"
```

승인 후 대기 오류의 원인: 요청 식별용 URI를 PendingIntent에 넣었지만 이전 IntentFilter는 URI를 허용하지 않아 결과가 전달되지 않았다.
URI 필터를 보완했으며, 이 계측 테스트의 실행과 실제 권한 창 검증은 연결된 기기에서 별도로 수행해야 한다.

- [ ] 미연결: 장치 없음 표시, 오류 없이 새로고침 가능.
- [ ] 앱 실행 전 연결: 최초 조회에 동글 표시.
- [ ] 앱 실행 중 연결: 이벤트 또는 새로고침으로 표시.
- [ ] 권한 전: 권한 없음 표시, 시리얼 접근 예외 없음.
- [ ] 권한 승인: 권한 있음으로 변경, 연결 확인 버튼 활성화.
- [ ] 권한 거부: 오류 안내 후 재요청 가능.
- [ ] 권한 대기 중 연속 클릭: 요청 중복 없음.
- [ ] 권한 대기 중 분리/취소: 요청 종료, 늦은 응답으로 연결되지 않음.
- [ ] 연결 확인: USB 연결 완료와 RF 미검증 표시.
- [ ] 연결 상태에서 분리/재연결: 이전 연결 제거, 새 권한 상태 재조회.
- [ ] 앱 백그라운드 중 분리 후 복귀: 올바른 목록 표시.
- [ ] 진단 창 닫기 및 다시 열기: 연결 해제 상태, 재연결 가능.
- [ ] 일반 USB 장치: 진단 화면은 표시하지만 접근 요청 금지.
- [x] 웹 브라우저: Android 전용 안내, USB 버튼 비활성화 (Chrome에서 확인).
